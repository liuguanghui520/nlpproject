# 初步设计：三方交叉评审记录

日期：2026-10-06；评审对象：[初步设计](初步设计.md) v0.1草案及修订至v0.2的方案。  
依据：[需求分析](需求分析.md)、[验收用例](验收用例.md)、[README](../../README.md)。  
性质：用户要求的3个子 agent 静态设计审查；不代表已执行程序测试、模型服务连通、人工事实金标或效果验收。

## 1. 综合结论

三方均认为 **Python + FastAPI + Pydantic + SQLite + 轻量网页 + 本地BM25 + 可替换模型适配** 与本机单任务课程项目规模相符，未发现必须推翻技术栈的阻塞。建议完成状态、取消、存储与实验隔离等细化后作为 M0/M1 实施基线。

主 agent 已把下面的15项意见合入初步设计v0.2；其中中文难例的实施阶段、金标隔离范围、存储耐久承诺经交叉复核收窄。评审中的 P1/P2 表示意见修正优先级，不改变需求文档既有 P0/P1/P2 功能优先级，也不说明需求P0已经验收通过。

## 2. 独立审查分工与过程

| 评审 | 子 agent 任务名 | 独立重点 | 首轮判断 |
|---|---|---|---|
| A | requirements_review | 双链语义、完整性、原文绑定、TR/FR/AC覆盖、范围偏移 | 总体合理；完整性/处理状态及分层用量契约需补齐 |
| B | engineering_review | 技术可落地性、执行器、取消、预算、SQLite/文件一致性、敏感字段 | 栈合理，无需增Redis或通用Agent框架；工程竞态与存储约束需明确 |
| C | evaluation_review | 中文检索、独立核验、修订终检、金标隔离、基线参数与课程交付 | 方法方向合理；数据泄漏防护、降级重绑、难例与实验适用性需具体化 |

三个子 agent 均读取同一需求、验收、设计草案和README，先独立提出意见。主 agent 汇总后向各方转发另外两方意见，开展第二轮交叉复核；主 agent 根据一致意见及范围约束修订文档。子 agent 没有编辑文件，修改由主 agent统一完成，避免并行覆盖。

## 4. 交叉复核的关键共识与收窄

**完整性与运行状态：** B/C认可A意见。trace审查工作可completed，同时记录完整性partial；默认双能力时有已证实日志缺口总partial。coverage_unknown允许完成约定审查，但范围未知持续可见。hash和外部平台自报完整性不证明原始真实性。

**取消、结算和删除：** A/C认可B意见，与事实核验方法不冲突。按实际attempt去重计费，取消终态与执行器静默分开；不引入另一个复杂计费服务，避免在删后重建记录。

**金标隔离：** A/B认可C意见，但强调允许原始参考证据正文与运行允许来源重叠。禁止进入运行的是人工标签、选片/对齐映射、指南、仲裁及各方案预测，不能因为某正文供人标注过就禁止检索该原始来源。

**降级最终文本：** A/B认可C意见。candidate终检结果不能直接给撤回后的组合文本背书；必须重绑实际输出，不受影响的同事实/同条件/同证据可以显式复用，其余保留未完成与保守注释。

**阶段范围：** C采纳A的收窄：M0验证真实记录、模型/资料可行性及代表性反馈，不把完整中文难例矩阵全部放进M0出口。fsync属于轻量实现细化，不扩大成重型耐久存储工程；断电恢复不作当前验收承诺。

## 5. 评审不能消除的风险与下一步

- 真实生成记录、具体模型供应商/版本/授权预算和独立参考资料仍须M0验证；拿不到日志时受控采集提升P0。
- 本地BM25对资料库外事实和中文近义表述可能缺证据；需真实试样与人工候选检查，不能仅凭架构断言召回足够。
- 同模型多阶段存在相关错误；最终效果必须由独立人工参考、误改/保留/删除/完整性指标联合评价。
- 文件/数据库跨介质、取消与单请求token估计仍有实现风险；静态意见合入不等于竞态/故障测试已通过。
- 当前没有实施代码、依赖安装、付费服务调用、发布或正式效果结果。下一步按设计M0/M1出口推进，不直接承诺课程成绩或质量阈值。

本次3个子 agent 是设计审查分工，不构成产品多智能体协商能力；其输出可用于AI辅助声明，不能伪作人工独立标注。
