① 超多分类：不可行

把“整句译文”当成一个类别，输出层是目标语言所有可能句子的 softmax。

类别数是 V 的 m 次方——天文数字，参数爆炸，也无法覆盖未见句子。

② 逐词分类：做不到

对每个源词独立预测一个目标词，长度被强制等于输入长度。

语序无法重排（中英主谓宾顺序不同）、增词与删词（冠词、量词）完全做不到。

③ 复制改写：不够用

从源句里挑片段重组，无法生成源句里没有的词（如译出英文冠词 the/a）。

摘要任务里也需要生成原文没出现过的概括性表达。

所以必须找一个能自由生成、长度不限、内容全新的架构——这就是编码器-解码器。

两个组件，各司其职
  • 编码器：读入源序列，输出定长的上下文表示 c（通常取最后一个时间步的隐状态）
  • 解码器：以 c 为条件，自回归逐词生成目标序列；每步的输入是上一步生成（或真实）的目标词

两个网络可以是 RNN、LSTM、GRU——本讲默认 LSTM。

这个类比最该记住的一点

译员必须先听完再开口（编码完成后才解码），而且他脑子里只带了一个固定大小的压缩包——句子越长，压缩损失越大。所以这个架构天生有一个瓶颈，下一页专门讲。

术语提醒：Encoder–Decoder、Seq2Seq、RNN Encoder–Decoder 指的都是这一套骨架。

架构公式：一行连乘背后的三件事环节二 · 知识点讲解 · 考点
目标（条件概率的链式分解）： P( y | x ) = ∏t=1..m P( yₜ | y₁ … yₜ₋₁ , c ) 训练（极大似然 → 取对数变求和）： maxθ Σ(x,y) ∈ D log P( y | x ) = Σ(x,y) Σt log P( yₜ | y₁ … yₜ₋₁ , c ) 编码器： hₜ = fenc( hₜ₋₁ , xₜ )　→　c = hₙ 解码器： sₜ = fdec( sₜ₋₁ , e(yₜ₋₁) , c )　→　P(yₜ) = softmax( W_o · sₜ + b )
① 就是链式法则

与第 7、8 讲的语言模型完全同构：都是逐词条件概率相乘。

唯一的区别是条件里多了一个 c（源句信息）。

② 历史是“目标端”的

条件 P(yₜ | y₁…yₜ₋₁, c) 里的历史是已经生成的目标词，不是源句的词。

源句只通过 c 进入。这一点最容易与第 9 讲的序列标注混淆。

③ c 与 t 无关

无注意力版本中，c 是一个常数向量，所有解码步共用同一个。

注意力的全部改动就是：把 c 换成随 t 变化的 cₜ。

编码器细节：BiLSTM 与隐状态交接环节二 · 知识点讲解
为什么常用 BiLSTM（第 8 讲双向 RNN 的直接应用） 前向：h→j = f( xj , h→j−1 ) j = 1 … n 后向：h←j = f( xj , h←j+1 ) j = n … 1 拼接：hj = [ h→j ; h←j ] ∈ R2h 每个位置同时看到左右全部上下文 “苹果”是水果还是公司，左右文一起裁决 无注意力时取上下文向量： c = [ h→n ; h←1 ] （两端各取最后状态，2h 维） 或 c = 池化( h₁ … hₙ )
三个必须记住的细节
  • 编码器真正输出的是隐状态序列 h₁…hₙ（每位置一个 2h 维向量）——注意力后面要全部用到
  • c 只是这个序列的一个特例：无注意力时把它压成一个向量
  • c 的维度是 2h（双向拼接），与句长 n 无关——这就是瓶颈的来源
一个伏笔

既然编码器已经算出了每个位置的 hj，为什么非要把它们压成一个 c 呢？把它们全部留着、解码时按需取用，不就是注意力吗？——下一页开始，我们顺着这个念头把模型改造一遍。

解码器细节：每一步输入什么环节二 · 知识点讲解 · 考点
自回归生成的四个要素
① 每步输入：e( yₜ₋₁ ) ← 目标端上一个词的嵌入 第一步：y₀ = <BOS>（启动符号，无语义） ② 状态更新：sₜ = fdec( sₜ₋₁ , e(yₜ₋₁) , c ) 初始状态：s₀ = tanh( W · c ) ← 源句信息从这里注入 ③ 输出分布：P( yₜ ) = softmax( W_o · sₜ + b ) ← 目标语言词表上的概率分布（|V| 维） ④ 终止条件：生成 <EOS> 或达到长度上限
四个易错点
  • 解码器的输入不是源句的词，而是目标端上一个词（或生成结果）；源句只经 c 进入
  • 编码器与解码器是两套独立参数，不共享权重
  • 解码器不能双向：生成第 t 个词时看不到后面的词（否则就是“抄答案”）
  • BOS / EOS 是特殊符号，必须加入词表并参与训练
<BOS> → s₁ → P(y₁) = I 第 1 步：输入 BOS，输出第一个词 I → s₂ → P(y₂) = am 第 2 步：把「I」喂回去 am → s₃ → P(y₃) = a 第 3 步：把「am」喂回去 a → s₄ → P(y₄) = student student→ s₅ → P(y₅) = <EOS> 第 5 步：生成结束符，停止
一句话：解码器是一台“把上一个词和源句信息揉在一起、吐出下一个词”的机器，逐词喂回自己。

训练与推理的不对称

训练：目标句的真实前缀全部已知，可以把它整句一次喂进解码器——1 次前向算完 m 个位置，损失一次算齐、梯度一次回传。

推理：只能生成一个词、把它喂回去、再生成下一个——m 次串行前向。

教学举例：目标句 20 词，训练 1 次前向，推理 20 次。“训练快、推理慢”是 Seq2Seq 的固有不对称（第 14 讲 KV Cache 要治的就是它）。

实现时的三个关键点
  • 训练时用 shifted right：解码器输入是 [BOS, y₁, …, y_{m−1}]，目标是 [y₁, …, y_m, EOS]
  • 用 mask 屏蔽 PAD 位置，损失只算有效 token
  • 把 c 作为解码器的初始状态（或作为每步的额外输入）——两种实现都可，需在报告中写明

架构易错点：五个高频误解环节二 · 知识点讲解
误解正确说法为什么会错
“c 是最后一个词的含义”c 是整句的定长压缩表示符号 c 取自最后一步（c = hₙ），看起来像局部量
“解码器每步输入源句的词”输入目标端上一步的词的嵌入；源句只经 c 进入与第 9 讲序列标注的“逐位置输入源词”混淆
“c 在每个解码步都会更新”无注意力版本中 c 是常数，所有步共用把有注意力的 cₜ 与无注意力的 c 混为一谈
“编码器和解码器共享参数”两套独立参数，各自训练受“参数共享”的 RNN 印象影响（共享发生在时间维，不是编码/解码之间）
“训练时用模型自己的预测”训练用真实前缀（教师强制）；用自预测会难以收敛没区分训练与推理两个阶段
一个自检方法

把符号写在纸上，逐个标注：这个量的形状是什么？它在哪一步被计算？它下一步喂给谁？三个问题答清楚，上面五条误解都不会犯。

信息瓶颈：一个固定向量装不下一个长句环节二 · 知识点讲解 · 考点
1容量视角

需求侧：源句信息量上界约 n · log₂V 比特，随手长 线性增长。

供给侧：c 的容量由维度 d 决定（如 512 或 1000），与 n 无关。

需求线性增长、供给恒定 → 必然有损压缩。5 个词的句子够用，50 个词就不够了。

2优化视角

c 由编码器在读完源句时一次性确定，却要同时对所有解码步负责。

因此它只能是所有位置的折中：偏向任何一处，都会牺牲其他处。

而这个折中发生在看到目标句之前——它无法知道后面会需要哪部分信息。

3近因效应

RNN 的隐状态天然偏向最近看到的词（第 8 讲的梯度衰减在起作用）。

结果是：句尾信息保留较好，句首信息衰减最快——而句首往往是主语，承载关键信息。

必须说清的一句判断

这个瓶颈是结构性的，不是训练不够：堆更多数据、换更大模型都不会让它消失，因为『容量常数 vs 需求线性』的矛盾写在架构里。唯一的出路是不要压成一个向量——保留全部隐状态，让解码器每步自己去取。

注意力计算：三步
① 打分 score
etj = a( st−1 , hj ) j = 1 … n
衡量当前解码状态与第 j 个源位置的相关性；原始分数可正可负、量纲任意、未归一化
② 归一化 softmax，对 j 做
αtj = exp(etj) / Σk exp(etk)
非负 + 整行加起来 = 1 → 可解释为“注意力分配比例”
③ 加权求和 生成动态上下文
cₜ = Σj αtj · hj ∈ R2h
不是取某一个 h_j，而是按权重混合出新的向量；维度与 h_j 相同（2h）
四个关键细节
  • 三步顺序不能换：先打分才能归一化，归一化后才能加权
  • softmax 是对源位置 j 做的（每个解码步做一次），不是对解码步做
  • c_t 的维度与 h_j 相同（2h）——但它是按需生成的，不再是被迫压缩
  • α 是权重比例，不是“选中某个词的概率”，全部位置都被加权混合
两个必背公式

αtj = softmaxj( a( st−1 , hj ) )

cₜ = Σj αtj hj

考试常考：写出这两式 + 说明每步在做什么 + 手算一个小例子。

c 不等于任何一个 h_j——它是三个向量的加权混合。

这正是软对齐能表达一对多 / 多对一关系的原因。

  • 早期模型输出全是错的，用自预测会让输入分布迅速跑偏，极难收敛

暴露偏差：训练与推理的输入错位环节二 · 知识点讲解 · 考点
定义与后果

三种缓解手段（都是缓解，不是根治）
  • 计划采样（scheduled sampling）：训练时以概率 ε 混入模型自己的预测，ε 随训练从 0 逐渐增大——让模型逐步适应“自己的错误”。代价：训练更慢、不稳定，实践收益有限
  • Beam search：推理时保留多个候选，降低单步错误造成的伤害
  • 数据与目标改造：加入噪声、用强化学习直接优化序列级指标（BLEU）

定义与复杂度

Beam Search：保留 k 条最优前缀环节二 · 知识点讲解 · 考点
算法（束宽 k = 2 的例子） ① 初始化：束 = { <BOS> : 1.0 } 空前缀，分数 1.0（log 空间为 0） ② 扩展：对束中每条前缀，计算「父分数 × P(w | 前缀)」 → 得到 k × V 个候选 ③ 剪枝：全局排序，只保留 top-k 条 ④ 终止：出现 <EOS> 的前缀移入「完成池」，不再扩展但保留比较 ⑤ 输出：在完成池 + 未完成前缀中选最终最优（需长度归一化）
三个实现要点
  • 累加对数概率而不是概率连乘——连乘会下溢变成 0
  • 已完成的前缀不再扩展，否则浪费束宽
  • 最后必须做长度归一化，否则系统性偏好短句（下一页详讲）
复杂度与参数选择

每步 O(k · V) 次打分（实际用矩阵运算批量做），总 O(m · k · V)——比 greedy 慢 k 倍，但远小于穷举 |V|m。

经验取值：机器翻译 k 常取 4–12；对话与摘要常用 3–5；实时场景可用 1–3。

一个反直觉的结论

k 越大不等于质量越高。Murray & Chiang 2018 的实证研究显示，BLEU 随 k 增大先升后降：束太宽会让模型倾向于“高概率但平庸”的句子，反而偏离人类偏好。

而且模型概率与人类质量评价并不完全一致，搜索得越彻底，有时越明显暴露这个偏差。

记忆锚点：beam search = 每一步都“保留几个最像样的草稿”，最后挑一份交卷。

长度归一化与覆盖惩罚环节二 · 知识点讲解 · 考点
隐蔽 bug：长度偏置

累计 logP 是一串负数相加，句子越长总分越低（越负）。

后果：beam 系统性偏好短句；极端情况下模型学会“早出 <EOS> 拿高分”——只生成一两个词就结束。

这是解码期的问题，不改模型参数、只改打分方式就能解决。

解法：长度归一化
score( y ) = ( Σt log P( yₜ | y<ₜ , x ) ) / Lα α = 0 → 原始 logP（偏好短句） α = 1 → 完全除以长度（可能偏好长句） α = 0.6–0.7 → 工业常用（GNMT 用 0.6）
覆盖惩罚（coverage penalty）
cp( y , x ) = β · Σj=1..n log( min( Σt αtj , 1.0 ) ) score = logP / Lα + cp( y , x ) β 常取 0.2–0.4

直觉：把每个源位置在整个解码过程中累计收到的注意力加起来。如果一个位置被反复过度关注（Σα 远大于 1），说明模型在“重复翻译同一处”；如果某个位置的累计注意力接近 0，说明“漏了”。

这个惩罚项会同时抑制重复与缓解漏译——GNMT 报告它带来明显提升。

一个重要的方法论

长度归一化与覆盖惩罚都属于解码期的后处理：模型没变、参数没变，只是改了一句排序规则，效果就有可观改善。“训练—解码—评估”三处都可以做优化，不要只盯着模型结构。

BLEU：机器翻译怎么自动打分环节二 · 知识点讲解 · 考点
总公式（Papineni 等，2002） BLEU = BP × exp( Σn=1..N wn · log pn ) N = 4（常用），wn = 1/N = 1/4 pn = 修正后的 n-gram 精确率 BP = 简短惩罚 Brevity Penalty
三个组件各管什么
  • p₁（unigram）：用词是否准确——词汇选对了没有
  • p₂–p₄：语序与搭配是否通顺——词组用得对不对
  • BP：防止“越短越占便宜”——短句要受罚

几何平均把四个层次的信息合成一个数，取值 0–1（常乘 100 写成百分数）。

最著名的脆弱点

因为用的是几何平均（对数后求平均再取指数），只要任何一个 p_n = 0，log 0 = −∞，整个 BLEU 就是 0。

所以一个译文即便 1–3 gram 全对、只有 4-gram 没匹配上，BLEU 也会是 0——这个性质在实际使用中非常容易造成误判。

为什么要 4 个 n-gram

只用 unigram 精确率，模型会倾向输出高频词堆砌（“the the the”）；只用高阶 n-gram 则过于苛刻、样本稀疏。

1–4 gram 的几何平均是一个折中：既看用词，也看短语与语序。

BLEU 的设计哲学：“机器译文里的 n-gram 有多少出现在参考译文里”——它是一个精确率导向的指标，天生不擅长衡量召回与语义。

修正规则（截断计数）
对于每个 n-gram w： Countclip(w) = min( 候选中的计数 , 参考中的最大计数 ) 本题： Countclip(“the”) = min( 7 , 2 ) = 2 修正后 p₁ = 2 / 7 ≈ 0.286

这个机制为什么重要
  • 它让 BLEU 不会因重复输出而虚高——朴素精确率做不到这一点
  • 它隐含了“参考译文里有的才算对”的保守立场，这也是 BLEU 偏向精确率的根源
  • 工程实现需注意效率：把候选的 n-gram 逐个与所有参考的计数比对，常用 Counter 提前汇总

漏洞与公式

漏洞：精确率导向 → 候选越短越容易“词词都在参考里”。只输出 the 一个词时 p₁ = 1，而高阶 n-gram 无定义，BLEU 虚高。

BP = 1 若 c > r BP = exp( 1 − r / c ) 若 c ≤ r c = 候选译文长度（词数） r = 有效参考长度 = 与 c 最接近的那个参考的长度
算几个数直观感受
c = 12, r = 12 → BP = 1 不惩罚 c = 10, r = 12 → exp(1 − 1.2) = 0.819 c = 6, r = 12 → exp(1 − 2.0) = 0.368 c = 3, r = 12 → exp(1 − 4.0) = 0.050 几乎归零

BP 只惩罚过短，不奖励过长——啰嗦的译文要靠精确率本身去扣分。

为什么用『最接近的参考长度』

同一句源文可以有不同长度的合法译文（例如中文“天亮了”可译为 “It's dawn.” 或 “The day has broken.”）。

如果固定用最短参考，会不公平地惩罚较长的正确译文；取最接近候选长度的那个参考，能更公平地判断“是否过短”。

一句话总结 BLEU 的两道补丁

截断计数防“重复刷分”；BP 防“越短越占便宜”。两者都是被实际漏洞逼出来的工程补丁——这也是所有自动评测指标的共同演化方式。

它们的共同结构都是：一段变长输入 → 一段变长输出，且两者之间存在某种（可能非单调的）对应关系。

复制机制：让模型既能“写”也能“抄”环节二 · 知识点讲解
纯生成式的两个缺陷

写不对事实与专名：训练语料里见过“东北大学”，但生成时可能写出“东方大学”——语义相近但事实错误。

未登录词只能输出 UNK：源句里的新公司名、新药名、数字、日期，词表里没有就写不出来。

容易重复：同一句话反复生成。

这些问题在摘要与对话场景尤其致命。

Pointer-Generator 的做法（See 等 2017）
① 生成门（软开关）： pgen = σ( wh·h*t + ws·st + wx·xt ) ∈ (0,1) ② 混合分布： P( w ) = pgen · Pvocab( w ) ← 从词表“写” + (1 − pgen) · Σj : x_j = w αtj ← 从源句“抄” ③ 对未登录专名：把 Pvocab(w) 置 0， 强制只能通过复制路径输出，避免 <UNK>
工程价值与代价

价值：专名、数字、日期不写错；同时仍能生成源句里没有的概括性表达（例如“该公司宣布……”）。

代价：需要复用注意力权重 α，实现比标准 seq2seq 稍复杂；p_gen 的可解释性有限。

这个思想的现代回声

今天所有 RAG 系统都面临同一个问题：答案里的专名与数字必须来自检索到的原文，不能由模型“编”。复制机制（检索结果 → 输出）的思路正是这类需求的源头，第 15 讲会把它工程化。

RNN 仍是瓶颈：通往 Transformer 的路标环节二 · 知识点讲解 · 考点
1串行瓶颈没有被解决

注意力只改变了『解码器读源句』的方式；编码器与解码器本身仍然是 RNN，必须一个时间步一个时间步算。

训练时序列长度为 n 就要 n 次串行计算，GPU 的并行能力大量闲置。

后果：模型无法通过单纯堆数据、堆算力来扩展——这在 2017 年数据爆炸的背景下成了硬伤。

2长距离依赖仍受限

注意力给了『解码器 → 编码器任意位置』的 O(1) 通路，但编码器内部的信息传递仍要穿过多步 RNN。

第 8 讲的梯度衰减仍在起作用：源句内部两个相隔很远的词，它们之间的信息依旧要“接力”传递。

Transformer 的解法（第 11 讲预告） ① 用自注意力替换编码器与解码器里的循环 → 序列内任意两个位置直接相连，路径长度 O(1) → 所有位置可以并行计算（矩阵乘一次算完整句） ② 用位置编码补回语序信息（自注意力本身与顺序无关） ③ 用多头注意力同时学习多种对齐关系（语法、语义、指代……） ④ 用残差 + LayerNorm 让深层网络稳定可训练
一句话：注意力解决了“读哪里”的问题，Transformer 解决了“怎么并行地读”的问题——而它用的仍然是今天学的打分→归一化→加权求和。

本讲小结环节四 · 小结
1架构与训练

编码器把源句压成 c；解码器以 c 为条件自回归逐词生成。

训练用教师强制（真实前缀，一次前向并行算完）；推理自由运行（自生成前缀，m 次串行）→ 由此产生暴露偏差。

2瓶颈与突破

固定 c 的容量与句长无关（结构性有损）→ BLEU 随句长断崖下跌。

注意力保留全部 h_j，用“打分 → 归一化 → 加权求和”每步重算 c_t：路径 O(1)、上下文动态、对齐成为副产品。

3解码与评估

greedy（快、可复现）／beam（质量好，需长度归一化）／采样（多样，配温度与 top-p）。

BLEU = BP × 几何平均 n-gram 精确率（含截断计数）；偏字面、抓不住漏译与同义改写，需配语义/召回类指标与人工评估。

一句话带走

注意力不增加信息，只改变读取方式——从“一次压缩、全程共用”变成“全部保留、按需加权读取”。同样的信息，换一种取用方式，效果就完全不同。这句话贯穿第 11 讲的 Transformer 与第 15 讲的 RAG。
