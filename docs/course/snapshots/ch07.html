Shannon 1951：猜词游戏与语言模型环节一 · 导入
现场猜一猜

核心问题：如何给一句话、给下一个词，赋一个概率？

语言模型：给语言一个概率分布环节二 · 知识点
两种等价表述
  • 整句概率：P(w₁, w₂, …, w_N)
  • 下一词分布：P(wₜ | w₁…wₜ₋₁)
  • 句界标记 <s> / </s>：让“开始/结束”也参与计算
能干什么
  • 打分：判断句子合理性、给候选重排（语音/翻译/纠错）
  • 预测：生成文本、输入法联想、搜索补全
  • 它不判断对错，只回答：这串词有多像真实语言
语言模型 = 把“像人话”变成一个可以比较的数。
东北大学软件学院 · 自然语言处理09
链式法则：精确，但没法估环节二 · 知识点
P(w₁, w₂, ..., w_N) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · ... · P(w_N | w₁...w_{N-1}) = Πt=1..N P(w_t | w₁ ... w_{t-1})
数学上：完全精确

概率乘法公式的直接应用，没引入任何近似——理论上毫无问题。

工程上：组合爆炸
  • 长度 t 的历史有 Vᵗ 种可能，语料里绝大多数没出现
  • MLE 遇到未见历史只能给出 0/0；精确公式 + 有限语料 = 不可用
连乘下溢
  • 30 个词、每词概率 0.1 → 整句 ≈ 1e-30
  • 浮点数很快下溢为 0——概率再也比不出大小
对数空间
log P(w₁...w_N) = Σ log P(w_t | history) # 乘法 → 加法；单调递增，比较结果不变 # log(0) = -∞：零概率连对数都取不了
连乘下溢 → 取对数；精确但不可估 → 引入近似（马尔可夫假设）——两条路都指向同一句工程常识。
东北大学软件学院 · 自然语言处理10
马尔可夫假设：主动“健忘”的智慧环节二 · 知识点
P(w_t | w₁ ... w_{t-1}) ≈ P(w_t | w_{t-n+1} ... w_{t-1})
近似换来了什么
  • 只看最近 n−1 个词——历史数从 Vᵗ 降到 Vⁿ⁻¹
  • n=2（bigram）：看前 1 个词；n=3（trigram）：看前 2 个
  • 参数可数、概率可估——终于能算了
代价：长程依赖失明
  • 窗口之外的信息全部丢弃
  • “我上周在图书馆借的那本书……”结尾的主语一致性，bigram 看不见
  • 这是结构性问题——第 8 讲 RNN 的动机
用一个可估的近似，换取可计算性——这是统计 NLP 的第一笔交易。
东北大学软件学院 · 自然语言处理11
Unigram → Bigram：从词袋到“数数”环节二 · 知识点
Unigram：P(w₁…w_N) ≈ Π P(wᵢ)　→　Bigram：P(w_t | w_{t-1}) = Count(w_{t-1}, w_t) / Count(w_{t-1}) # 词袋：完全忽略顺序　　# 数数：分子 = 相邻词对次数；分母 = 前缀（历史）次数
Unigram：词袋
  • 参数最少（V 个），估计最稳——最弱但最快的语言模型
  • 代价：语序信息全丢
现场对照
  • “我喜欢吃苹果” vs “苹果吃我喜欢”
  • Unigram 给两句相同概率，语感却天差地别——它看不见语序
为什么分母是前缀计数
  • 保证同一历史下所有下一个词的概率之和为 1（归一化）
  • 直觉：P(Sam|am) = “am Sam”次数 ÷ “am”次数
模型长什么样

一张 V×V 的条件概率表：行 = 历史词，列 = 下一个词，格子 = 概率——又大又稀疏。

从词袋到条件概率：MLE 在 N-gram 上就是数数——这是统计 NLP 的核心操作。

N-gram 家族：公式与 Vⁿ 参数爆炸环节二 · 知识点
P(w_t | w_{t-n+1} ... w_{t-1}) = Count(w_{t-n+1} ... w_t) / Count(w_{t-n+1} ... w_{t-1})
模型看多长的历史参数量（V=5 万）特点
Unigram0 个词（词袋）5 万最稳但丢语序
Bigram前 1 个词25 亿常用、稀疏
Trigram前 2 个词12.5 万亿效果好但极稀疏
4/5-gram前 3–4 个词天文数字需大语料 + 强平滑
n 越大越准，但参数按 Vⁿ 爆炸——工程上常见 bigram/trigram + 平滑。
东北大学软件学院 · 自然语言处理14
困惑度 PPL：语言模型的“体温计”环节二 · 知识点
PPL(W) = P(w₁ ... w_N)-1/N = exp( -(1/N) · Σ log P(w_t | history) ) # N = 被预测的 token 数：不含句首 <s>，含句尾 </s>
直觉：平均分支因子
  • PPL = 100：每步像在 100 个等可能词里猜
  • PPL = 10：只在 10 个里猜——更有把握
  • 越小越好；只在同词表/同分词下可比
两个极点
  • PPL = 1：完全确定——不可能，语言有内在熵
  • PPL = V：词表里均匀瞎猜——模型的地板
  • 模型的努力：从 V 向 1 逼近，但永远到不了 1
困惑度 = 平均在几个词之间犹豫——犹豫越少，模型越好。

PPL = 2^H：与交叉熵是一枚硬币环节二 · 知识点
等价关系
  • 交叉熵 H（比特/词）= −(1/N)Σ log₂ P(wᵢ|history)
  • PPL = 2^H——困惑度是交叉熵的指数
  • H 越小越好；PPL 把 H 换算成“平均候选数”
优缺点
  • 优点：单个数、易比较、与语言内在结构相关
  • 缺点：依赖词表与分词；不反映语义与下游任务表现
  • 选型仍以外在任务为准——第 5 讲评估观回响
内在评估（PPL）管“快”，外在评估管“准”——两者配合使用。
东北大学软件学院 · 自然语言处理17
零概率灾难与 Zipf 律环节二 · 知识点
零概率的连锁灾难
  • 测试句有一个未见 bigram → 整句概率 = 0
  • 对数空间 → −∞；困惑度 → ∞
  • 一个没见过的搭配，就能让整个评估崩溃
# 例：语料里从未出现过「深度学习 很香」 Count(深度学习, 很香) = 0 P(很香 | 深度学习) = 0 / Count(深度学习) = 0 P(整句) = … × 0 × … = 0 → PPL = ∞

MLE 只会“数数”：计数为 0，概率就是 0——它没有“也许”这个选项。

根源：Zipf 律
f(r) ∝ 1 / rα（自然语言 α ≈ 1）　→　排名 r × 频率 f ≈ 常数
词频排名 r12310100
相对频率 f(r)11/21/31/101/100
若第 1 名 = 1000 次100050033310010
  • 少数高频词吃掉大部分词次：英语中 the 约占 6–7%，前 100 个高频词合计约覆盖一半词次
  • 长尾极长：许多语料里约一半词型只出现 1 次——绝大多数词是“稀有词”
  • 语料扩大也甩不掉长尾：新词、新搭配不断冒出 → 未见 n-gram 是结构性的；n 越大，未见比例越高
语言分布天生“长尾”：没见过 ≠ 不可能——MLE 却判它 0 概率，平滑因此是必修。

平滑家族：给没见过的事件分一点概率环节二 · 知识点
思路做法一句话代表方法
① 加常数把每个计数都加一个常数 kAdd-1（Laplace）、Add-k
② 回退高阶没见过就降级用低阶Katz Backoff、stupid backoff
③ 插值高低阶概率加权混合，永远都听线性插值、Witten-Bell
④ 折扣按统计规律给高频打折、补给低频Good-Turing、Kneser-Ney
三个要件：分概率给未见 · 给见过打折 · 保证归一化——任何平滑方法都要满足。
东北大学软件学院 · 自然语言处理19
平滑①：Add-1 / Add-k——最简单的补丁环节二 · 知识点
P(w_t | w_{t-1}) = ( Count(w_{t-1}, w_t) + k ) / ( Count(w_{t-1}) + k·V )
优点
  • 简单、保证无零概率
  • k=1 即 Laplace 平滑——最好的教学基线
  • 文本分类等任务仍实用
问题：过于激进
  • V 很大时，大量概率被分给从未出现的组合
  • 高频词被严重打压——教材实测语言建模表现差
  • Add-k（k≈0.01–0.1）稍好；语言建模仍要回退/插值/KN
Add-k 是最好的入门基线，但不是最终答案——“一刀切”的折扣不够聪明。
东北大学软件学院 · 自然语言处理20
平滑②③：回退 vs 线性插值环节二 · 知识点
回退 Backoff：逐级请示
  • 高阶计数足够 → 用高阶；不够 → 降级用低阶
  • Katz：折扣省下的概率质量按低阶分布分配
  • stupid backoff：简化版，工程常用（不保证归一化）
插值 Interpolation：三人投票
  • P = λ₃·P₃ + λ₂·P₂ + λ₁·P₁，Σλ = 1
  • 每一阶都参与，永远不浪费低阶信息
  • λ 可在验证集上用 EM 学习——语言建模最常用
回退是逐级请示，插值是三人投票——插值通常更稳。
东北大学软件学院 · 自然语言处理21
平滑④：Good-Turing——让数据自己说打几折环节二 · 知识点
核心公式与思想
  • N_c = 恰好出现 c 次的 n-gram 种数（计数的计数）
  • 折扣计数：c* = (c+1)·N_{c+1} / N_c
  • 未见事件的总概率 ≈ N₁ / N
出身与地位
  • 1953 年发表，源自图灵二战破译密码的统计工作
  • “只见过一次”的事物，是“还没见过”的代言人
  • 现代用 Kneser-Ney，但 GT 的思想影响至今
GT 的美：不拍脑袋定折扣，让数据自己说该打几折。
东北大学软件学院 · 自然语言处理22
平滑⑤：Kneser-Ney——统计平滑的集大成者环节二 · 知识点
两个核心机制
  • 绝对折扣：所有非零计数统一减去常数 d，省下的概率给未见事件
  • 延续性：低阶概率用“前面接过多少个不同的词”估计——P_cont(w) ∝ |{v : Count(v,w)>0}|
经典例子与地位
  • Francisco 出现多，但前面几乎只接过 San——延续性计数低，符合直觉
  • modified KN（三档折扣+插值）= 世纪之交的标准基线
  • Chen & Goodman 实证比较的结论
绝对折扣管“分钱给未见”，延续性管“谁更有资格接手”。

没有“最好”的平滑，只有与语料规模、n 大小、实现成本匹配的取舍。

OOV 与 <UNK>：给陌生词一个身份环节二 · 知识点
做法：闭词表 + 垃圾桶
  • 出现次数 < 5（或其它阈值）的词 → 统一映射为 <UNK>
  • <UNK> 同样参与计数与概率估计，保证归一化
  • 未知词概率 = 所有低频词合计概率，而非单次计数
词表大小 L 的取舍
  • L 越大：覆盖率越高，但参数越多、越稀疏
  • L 越小：参数少、统计稳，但 OOV 比例高
  • 中文要先分词再映射（第 4 讲伏笔）
OOV 处理 = 在覆盖率与稀疏度之间找一个平衡点。

import random def generate(model, gram, max_len=20): hist = ("<s>",) * (gram - 1) # 初始上下文 out = [] for _ in range(max_len): cands = model.get(hist) # 条件分布 if not cands: break w = random.choices(*zip(*cands)) # 按概率采样 if w == "</s>": break out.append(w); hist = (hist + (w,))[-(gram-1):] return " ".join(out)
典型现象
  • 局部像样：相邻搭配正确（学到了局部统计）
  • 全局胡说：越长越跑偏（长程依赖丢失）
  • 这正是语言模型生成能力的雏形——GPT 的逐 token 生成与它同构

N-gram 的三个死穴 → 神经 LM环节二 · 知识点
1长程依赖失明

只看最近 n−1 个词，窗口外信息全丢。
神经 LM：隐状态/注意力携带长程信息。

2稀疏与泛化差

没见过的组合就是零，平滑只是缓解。
神经 LM：词向量让相似上下文互相泛化。

3参数爆炸

Vⁿ 表格无法随语料扩展。
神经 LM：参数共享、低维稠密、规模可控。

N-gram 给了任务与评估坐标系（PPL）——第 8 讲只换引擎，不换问题。

1PPL 越小任务一定越好

自学任务：20 行建一个会“算命”的模型环节三 · 线下自学
import math, collections def train(corpus, k=0.1): uni, bi = collections.Counter(), collections.Counter() for s in corpus: toks = ["<s>"] + s.split() + ["</s>"] for a, b in zip(toks, toks[1:]): uni[a] += 1; bi[(a, b)] += 1 V = len(uni) + 1 # +1 给 <UNK> P = lambda a, b: (bi[(a,b)] + k) / (uni[a] + k * V) return P, V def ppl(sent, P, V): toks = ["<s>"] + sent.split() + ["</s>"] lp = [math.log(P(a, b)) for a, b in zip(toks, toks[1:])] return math.exp(-sum(lp) / len(lp)) # P, V = train(corpus); ppl("i am sam", P, V)
①训练与统计
  • 在课程语料上训练 bigram，输出词表大小与 bigram 数
  • 对三个测试句计算 PPL（含 OOV 句）——先映射 <UNK> 再看差异
②调参与挑战
  • 把 k 从 0 → 0.1 → 1.0，记录 PPL 变化并解释趋势
  • 挑战：把 bigram 换成 trigram（zip 窗口改一行）
  • 验收：三组 PPL 数值 + 一段解释
CPU 即可、纯标准库——亲手看到 PPL 随平滑参数变化，胜过十页公式。
