东北大学软件学院 · 自然语言处理05
英文靠空格，中文为什么难？环节一 · 导入
英文的空格就是分词器

The cat sits on the mat——空格天然把词隔开，split(' ') 就算分完了。

中文没有这个福利：猫坐垫子上，字与字直接相连，机器必须自己判断“词”从哪开始、到哪结束。

三重困难
  • ① 无分隔符：词边界不写在句子里，要靠词典和概率去猜
  • ② 歧义：结婚的和尚未结婚的——怎么切？第 12 页揭晓
  • ③ 新词：内卷、破防、搭子、Citywalk——词典永远追不上造词速度
英文的词边界是写出来的，中文的词边界是猜出来的——这就是中文分词的全部困难，也是本讲要解决的核心问题。

Token 到底是什么？一词多义环节二 · 知识点
Token 本义 = “不可再分的最小可交换单位”；在 NLP 里是文本切分后的最小处理单位——不是字，也不是词。
① NLP 本义
  • Unbelievable → Un / belie / vable 三个 token
  • “自然语言处理” → 自然 / 语言 / 处理
  • Token 是“出现”，Type 是“种类”（下一页展开）
② 大模型视角
  • 每个 token 对应词表里一个整数 ID
  • 计费与上下文窗口的最小单位
  • 生成时“逐 token”输出——步进单位
③ 编译原理
  • lexer 把源码切成词法 token
  • int x = 1; → int / x / = / 1 / ;
  • 关键字、字面量、运算符都是 token
④ 网络安全
  • JWT、OAuth、API Key、CSRF token
  • 登录后凭 token 验明身份
  • “最小的身份凭证”
⑤ 金融科技
  • 代币 / 通证：加密资产、积分、权益
  • “最小价值载体”——呼应学院金融方向
⑥ 心理 / 游戏
  • 代币制（token economy）：代币作行为强化物
  • 棋类与游戏里的棋子 / 游戏币也是 token
共同内核：不可再分的最小可交换单位——语言的处理单位、计费的最小单位、身份的凭证、价值的载体。

术语地基：Token / Type / 词表 / OOV环节二 · 知识点
the cat sat on the mat
  • Token（词例）：切分后的每一次出现 → 共 6 个
  • Type（词型）：去重后的不同 token → 共 5 个
  • 词表（Vocabulary）：全部 type 的集合，每个 type 配一个整数 ID
  • Token 回答“说了多少”，Type 回答“会说几种”
OOV：词表查不到怎么办
  • 新词、拼写变体、专名、错字……查不到的叫 OOV（未登录词）
  • 经典对策：一律替换成 [UNK]——信息全部丢失
  • 这是词级方法的死穴，本讲后半程的子词就是来破它的
词表大小是模型的第一超参数：大了稀疏，小了 OOV 泛滥——这个两难贯穿全讲。

粒度之争：词 / 字 / 子词环节二 · 知识点
粒度切分示例优点致命伤
词级[I, love, natural, language, processing]语义完整、序列短词表爆炸、OOV、中文先分词
字级[I, l, o, v, e, …] / 中文逐字词表极小、永不 OOV序列过长、单字语义稀薄
子词[un, believ, able] / [自然, 语言, 处理]词表可控、OOV 消失、序列适中切分与语言学“词”不总一致
one-hot 三大死穴
  • 维度灾难：词表 50 万 → 每个词 50 万维，几乎全 0
  • 语义鸿沟：任意两词的 one-hot 正交，“猫/狗”与“猫/汽车”一样远
  • OOV 无解：词表外的词连编号都分不到，只能丢成 [UNK]

伏笔：怎么让向量自己长出语义？——第 5 讲词向量的入口问题。

工业界的答案：子词（subword）——常见词整存，生僻词拆碎，两头的好处都要。

中文分词：与“词边界”搏斗三十年环节二 · 知识点
歧义：语法都通，语境裁决
  • 南京市长江大桥 → 南京市/长江大桥？还是 南京市长/江大桥？
  • 结婚的和尚未结婚的 → 和尚？还是 尚未？

更深的问题：“词”本身没有标准
  • “北大”“红烧肉”算一个词还是两个？

既然“词边界”连人类都意见不一，干脆不让模型依赖词边界——这正是子词路线的深层动机。

最大匹配法：贪心切词（含代码）环节二 · 知识点
算法三步（前向 FMM）
  • ① 从当前位置取长为 L（词典最长词长）的窗口
  • ② 窗口在词典 → 整词切走，窗口右移
  • ③ 不在词典 → 末尾删一字再试；删到 1 字还不命中 → 单字切走
def fmm(sent, vocab): max_len = max(len(w) for w in vocab) words, i = [], 0 while i < len(sent): for L in range(min(max_len, len(sent)-i), 0, -1): w = sent[i:i+L] if w in vocab: words.append(w); i += L; break else: words.append(sent[i]); i += 1 # OOV 单字 return words
现场失败案例

词典最长词长 L=3，词典含：研究 / 研究生 / 生命 / 起源。

  • 句子：研究生命起源
  • 窗口“研究生”命中 → 切 研究生；剩“命起源”
  • “命”单字 → 切 命；剩“起源” → 切 起源
  • 结果：研究生 / 命 / 起源 ✗
  • 正确：研究 / 生命 / 起源 ✓
贪心 + 只看词典 + 不看语义 = 必然犯的错——复杂度近线性、完全可解释，日志切分等轻量场景至今仍在服役。

歧义句：规则方法撞上天花板环节二 · 知识点
经典歧义句：结婚的和尚未结婚的
  • FMM（从左）：结婚 / 的 / 和尚 / 未 / 结婚 / 的
  • RMM（从右）：结婚 / 的 / 和 / 尚未 / 结婚 / 的 ✓
  • 语义上应是“和 / 尚未”——FMM 切出了荒谬的“和尚”
双向最大匹配（BMM）
  • 同时跑 FMM 与 RMM：结果相同 → 直接采用
  • 结果不同 → 取词数更少（粒度更粗）或单字更少者
  • 经验上 RMM 略准于 FMM——中文中心词常在后

但这仍是启发式，不是正解——规则到顶了，下一页换概率。

规则方法的天花板：没有上下文参与，歧义永远无解——必须让“概率”登场。

jieba：词典 + DAG + 动态规划环节二 · 知识点
1前缀词典（Trie）

把词典建成前缀树：从“研”出发快速查到 研究/研究生，O(字长) 查词。

2建 DAG

扫描句子，把“所有能成词的切法”连成有向无环图——节点是字位置，边是一种切法。

3DP 找最大概率路径

边权重 = 词频对数概率；用 DP 选总概率最大的切分路径——又一次动态规划。

未登录词：HMM + BMES 序列标注

词典里没有的新词（“破防了”“Citywalk”）：对成单字的片段跑 HMM + Viterbi，给每个字打标签 B词首 / M词中 / E词尾 / S单字——“自然语言处理”→ 自/B 然/E 语/B 言/E 处/B 理/E；“我爱北京天安门”→ 我/S 爱/S 北/B 京/E 天/B 安/M 门/E。这是序列标注，第 9 讲 NER 的 BIO 是它的近亲。

分词从“贪心取最长”升级为“图上找最可能的路径”——词典管熟词，统计管生词。

子词动机：词级词表的三宗罪环节二 · 知识点
词级词表的三个致命伤
  • ① 词表爆炸：英文几十万词含变形，首层嵌入表就可能上亿参数，长尾词学不好
  • ② OOV：新词、人名、品牌名一律变 [UNK]，模型“瞎”了
  • ③ 形态盲：run / runs / running 被当成四个毫无关系的词
子词：在“整词”与“单字”之间
  • unhappy → [un, happy]；ChatGPT → [Chat, G, PT]；猫 → [猫]
  • 任何词都能由已知碎片拼出，OOV 基本消失
  • 词表大小可控（常见 3 万–20 万），常见词整存、生僻词拆碎
  • 路线一自底向上：BPE / WordPiece；路线二自顶向下：Unigram
词级词表“见词不识词”——要么词表大到爆炸，要么新词变 [UNK]，子词就是来破局的。
东北大学软件学院 · 自然语言处理14
BPE：让词表从字符里“长”出来环节二 · 知识点
训练三步循环
  • ① 初始化：词表 = 全部字符，每个词尾加 </w> 标边界
  • ② 统计：全语料相邻符号对的频率，取最高频一对
  • ③ 合并：该对合并为新符号入词表、全语料替换；回到 ② 直到词表达标

词表大小 ≈ 字符数 + 合并轮数 K——K 就是“词表旋钮”。

来历与关键性质
  • Gage（1994）数据压缩算法；Sennrich et al.（2016）引入 NMT 分词
  • 高频片段先合并成“整词”——常见词自动完整保留
  • 生僻词拆不成整词——自然落在有意义碎片上
  • 纯数据驱动、零语言学知识；编码按合并顺序（rank）贪心回放
一句话：词表不再预先存在，而是从语料的共现统计里长出来——这是子词革命的第一性原理。

BPE 代码：30 行训练你自己的词表环节二 · 知识点
import re, collections vocab = {"l o w </w>":5, "l o w e r </w>":2, "n e w e s t </w>":6, "w i d e s t </w>":3} def get_stats(v): # 数相邻 pair 频率 pairs = collections.Counter() for word, freq in v.items(): s = word.split() for i in range(len(s)-1): pairs[(s[i], s[i+1])] += freq return pairs def merge_vocab(pair, v): # 全语料替换该对 bigram = re.escape(' '.join(pair)) p = re.compile(r'(?<!\S)' + bigram + r'(?!\S)') return {p.sub(''.join(pair), w): f for w, f in v.items()} for i in range(10): # 合并轮数 = 词表旋钮 pairs = get_stats(vocab); best = max(pairs, key=pairs.get) if not pairs: break vocab = merge_vocab(best, vocab) print(i+1, ''.join(best)) # 1 es 2 est 3 est</w> 4 lo …
30 行、纯标准库——合并次数就是词表旋钮：10 轮是碎片，20 轮几乎全是整词。

BPE 训练：数据预处理四道工序环节二 · 知识点
1预切分

按空格/标点切成初始单元；GPT-2 起在字节级做，任何输入可编码。

2词频统计

合并依据是频次——低质量样本先清洗（第 2 讲三件套）。

3词尾标记

加 </w> 区分词边界，否则合并会跨词“串味”。

4规模控制

WordPiece：不看频次，看“似然最大”环节二 · 知识点
与 BPE 的唯一区别：合并准则
  • BPE：选“共现次数最多”的 pair
  • WordPiece：选“合并后使语料似然概率最大”的 pair
  • 近似打分：score = freq(ab) ÷ (freq(a)·freq(b))
直觉与细节
  • 偏爱“组合出人意料”的对——合并后语料变得更可能才合
  • 用 ## 标记续接：playing → play + ##ing
  • Schuster & Nakajima（2012）语音搜索提出；BERT（2018）推广
一句区别：BPE 看谁出现多，WordPiece 看谁合并后让数据更“可能”——代表模型：BERT 系。

Unigram：先做大，再剪枝环节二 · 知识点
与 BPE 反着来（自顶向下）
  • ① 先建超大候选词表（所有字符 + 大量子串）
  • ② 训练一元语言模型，估每个子词概率
  • ③ 每轮删掉“删后语料似然损失最小”的一批子词
  • ④ 反复剪枝，直到词表大小达标
独门绝技与编码
  • 子词正则化：同一词可随机多种切分，训练时增强鲁棒性
  • 编码：用 Viterbi 选“总概率最大”的切分——又一次 DP
  • 代表模型：T5、ALBERT、gemma（Kudo 2018）
BPE 是从少往多“加”，Unigram 是从多往少“减”——殊途同归，都到一个可控词表。

Unigram 编码：Viterbi 实例环节二 · 知识点
编码“低音炮”：比较所有合法切法，选概率乘积最大者（示意概率）：
切法概率乘积结果
低 / 音 / 炮0.40 × 0.30 × 0.25 = 0.030✗
低音 / 炮0.35 × 0.25 = 0.0875✗
低音炮0.20✓ 最大
不是贪心最长，而是全切法枚举求最优——与第 3 讲 DP、第 9 讲 Viterbi 同一骨架。

SentencePiece：语言无关的框架环节二 · 知识点
解决了什么痛点
  • BPE / WordPiece 都要先预分词（用空格切开）
  • 可中文没有空格——预分词本身就是难题
  • SentencePiece 直接在原始裸文本上训练，把空格当普通字符
两点革命与生态
  • 语言无关：空格编码为符号 ▁，中英日一视同仁
  • 可逆：空格也是 token，切分结果能无损拼回原文
  • 内部引擎二选一：BPE 或 Unigram；LLaMA 系 / T5 / ALBERT 用它
不依赖空格，自然中英同一条流水线——这是现代中文 LLM 多用 SentencePiece 的根本原因。

SentencePiece：训练参数与流程环节二 · 知识点
import sentencepiece as spm spm.SentencePieceTrainer.train( input="corpus.txt", model_prefix="sp", model_type="bpe", # bpe 或 unigram vocab_size=32000, # 词表旋钮 character_coverage=1.0, # 中文建议 1.0 input_sentence_size=1000000) sp = spm.SentencePieceProcessor(model_file="sp.model") sp.encode("我爱北京天安门", out_type=str) # → ['▁我爱', '北京', '天安门']

  • model_type：BPE 或 Unigram
  • vocab_size：词表大小（32K/50K 常见）

  • input_sentence_size：采样句数控制训练时长
参数即词表旋钮——vocab_size 与 character_coverage 是三角权衡的落地开关。

四子词算法：一张表收口环节二 · 知识点
算法方向选谁合并 / 删谁的准则代表模型
BPE自底向上选共现频次最高的相邻 pair 合并GPT 系、LLaMA、tiktoken

字节级 BPE：连 [UNK] 都不要了环节二 · 知识点
从“字符”到“字节”
  • GPT 系用字节级 BPE（BBPE）：初始字母表是 256 个字节
  • 任意 Unicode（生僻字、emoji）都能退到字节——理论上不存在 [UNK]
  • SentencePiece 的 byte_fallback 同源，工业 tokenizer 标配
代价：中文更费 token
  • 生僻中文字可能被拆成 2~3 个字节 token
  • 序列变长、账单变贵、上下文窗口更不经用
  • 导入页“一个汉字几个 token”的答案就藏在这里
把字母表压到字节，换来“任何输入都不会被 [UNK] 拒之门外”——代价是中文多花几个 token。

为什么 LLM 都用子词：三角权衡环节二 · 知识点
1词表大小

嵌入矩阵参数 = V × d；子词把 V 稳在 3 万–25 万，内存与计算可控。

2覆盖率

任何文本都能由碎片拼出 → OOV 从词典里被删除，新词、代码、表情全覆盖。

3序列长度

常见词保持完整 → 远短于字级；注意力计算量随长度平方增长（第 11 讲展开）。

红利：形态学免费送（un + belie + able）；副作用：中文被英文主导的词表切得偏碎、更费钱——子词是三点全及格的工程甜点。

三个常见误区：作业前先避坑环节二 · 知识点
1混淆“分词”与“子词化”

中文分词是词级切分（jieba）；子词 token 化是喂模型前的编码（BPE）——粒度、目的都不同，作业 2 对比的正是它俩。

2以为 BPE 必须先分词

BPE 本身依赖预分词，但 SentencePiece 直接吃裸文本——这正是它对中文友好的原因，别再去手工切一遍。

3以为词表越大越好

词表大 = OOV 少，但嵌入参数多、中文更费 token——这是权衡，不是越大越优。

分词是给人读的索引，子词是给模型吃的原料——别把两道工序当成一件事。

BPE 编码：按 rank 贪心回放环节二 · 知识点
def encode(word, merges): symbols = list(word) + ['</w>'] while True: pairs = list(zip(symbols, symbols[1:])) i, j = min((p for p in pairs if p in merges), key=lambda p: merges[p], default=(None,None)) if i is None: break symbols = merge_pair(symbols, i, j) return symbols
lowest 的编码过程
  • 字符：l o w e s t </w>
  • rank1：e+s → es；rank2：es+t → est
  • rank3：est+</w> → est</w>；rank4：l+o → lo
  • 结果：[lo, w, est</w>]——OOV 就这样被拼出来
训练决定合并顺序（rank），编码只是按顺序回放——同一词表，切分结果唯一确定。

本讲小结环节四 · 小结
1粒度

词级保语义、字级保覆盖，子词两头兼顾——词表大小 × 覆盖率 × 序列长度的帕累托最优。

2算法

BPE：从字符按频率合并，词表“长出来”，编码按 rank 回放；WordPiece 换准则、Unigram 换方向、SentencePiece 统一封装。

3系统

tokenizer 是 LLM 第一道工序：计费、上下文窗口、多语言公平性皆出于此；中文词边界被绕过，中英同一起跑线。

一句话带走：词表不是编出来的，是长出来的——数据驱动的切分，让“词”第一次由语料自己定义。
