第 11 页：Seq2Seq 架构：一个同声传译员的比喻 环节二 · 知识点讲解 Seq2Seq 模型结构 目标句（解码器逐词生成） y₁ y₂ y₃ ↑ ↑ ↑ s₁ → s₂ → s₃ 解码器 Decoder：每步的输入是上一步的输出 ↑ c 作为解码器的初始状态注入 c 上下文向量（定长压缩包） ↑ 取编码器最后一个时间步的隐状态 h₁ → h₂ → h₃ → h₄ ↑ ↑ ↑ ↑ x₁ x₂ x₃ x₄ 源句（编码器一次读完）· Je suis étudiant 两个组件，各司其职 编码器 ：读入源序列，输出 定长 的上下文表示 c（通常取最后一个时间步的隐状态） 解码器 ：以 c 为条件， 自回归 逐词生成目标序列；每步的输入是上一步生成（或真实）的目标词 两个网络可以是 RNN、LSTM、GRU——本讲默认 LSTM。 这个类比最该记住的一点 译员必须 先听完 再开口（编码完成后才解码），而且他脑子里只带了一个 固定大小的压缩包 ——句子越长，压缩损失越大。所以这个架构天生有一个瓶颈，下一页专门讲。 术语提醒： Encoder–Decoder、Seq2Seq、RNN Encoder–Decoder 指的都是这一套骨架 。 东北大学软件学院 · 自然语言处理 11
第 12 页：架构公式：一行连乘背后的三件事 环节二 · 知识点讲解 · 考点 目标（条件概率的链式分解）： P( y | x ) = ∏ t=1..m P( yₜ | y₁ … yₜ₋₁ , c ) 训练（极大似然 → 取对数变求和）： max θ Σ (x,y) ∈ D log P( y | x ) = Σ (x,y) Σ t log P( yₜ | y₁ … yₜ₋₁ , c ) 编码器： hₜ = f enc ( hₜ₋₁ , xₜ ) → c = hₙ 解码器： sₜ = f dec ( sₜ₋₁ , e(yₜ₋₁) , c ) → P(yₜ) = softmax( W_o · sₜ + b ) ① 就是链式法则 与第 7、8 讲的语言模型完全同构：都是逐词条件概率相乘。 唯一的区别是条件里多了一个 c （源句信息）。 ② 历史是“目标端”的 条件 P(yₜ | y₁…yₜ₋₁, c) 里的历史是 已经生成的目标词 ，不是源句的词。 源句只通过 c 进入。这一点最容易与第 9 讲的序列标注混淆。 ③ c 与 t 无关 无注意力版本中，c 是一个 常数向量 ，所有解码步共用同一个。 注意力的全部改动就是：把 c 换成随 t 变化的 cₜ 。 东北大学软件学院 · 自然语言处理 12
第 13 页：编码器细节：BiLSTM 与隐状态交接 环节二 · 知识点讲解 为什么常用 BiLSTM（第 8 讲双向 RNN 的直接应用） 前向：h→ j = f( x j , h→ j−1 ) j = 1 … n 后向：h← j = f( x j , h← j+1 ) j = n … 1 拼接：h j = [ h→ j ; h← j ] ∈ R 2h 每个位置同时看到左右全部上下文 “苹果”是水果还是公司，左右文一起裁决 无注意力时取上下文向量： c = [ h→ n ; h← 1 ] （两端各取最后状态，2h 维） 或 c = 池化( h₁ … hₙ ) 三个必须记住的细节 编码器真正输出的是 隐状态序列 h₁…hₙ （每位置一个 2h 维向量）——注意力后面要全部用到 c 只是这个序列的一个 特例 ：无注意力时把它压成一个向量 c 的维度是 2h （双向拼接），与句长 n 无关 ——这就是瓶颈的来源 一个伏笔 既然编码器已经算出了每个位置的 h j ，为什么非要把它们压成一个 c 呢？ 把它们全部留着、解码时按需取用，不就是注意力吗？ ——下一页开始，我们顺着这个念头把模型改造一遍。 东北大学软件学院 · 自然语言处理 13
第 14 页：解码器细节：每一步输入什么 环节二 · 知识点讲解 · 考点 自回归生成的四个要素 ① 每步输入： e( yₜ₋₁ ) ← 目标端上一个词的嵌入 第一步：y₀ = <BOS>（启动符号，无语义） ② 状态更新：sₜ = f dec ( sₜ₋₁ , e(yₜ₋₁) , c ) 初始状态：s₀ = tanh( W · c ) ← 源句信息从这里注入 ③ 输出分布：P( yₜ ) = softmax( W_o · sₜ + b ) ← 目标语言词表上的概率分布（|V| 维） ④ 终止条件：生成 <EOS> 或达到长度上限 四个易错点 解码器的输入 不是源句的词 ，而是目标端上一个词（或生成结果）；源句只经 c 进入 编码器与解码器是 两套独立参数 ，不共享权重 解码器 不能双向 ：生成第 t 个词时看不到后面的词（否则就是“抄答案”） BOS / EOS 是 特殊符号 ，必须加入词表并参与训练 <BOS> → s₁ → P(y₁) = I 第 1 步：输入 BOS，输出第一个词 I → s₂ → P(y₂) = am 第 2 步：把「I」喂回去 am → s₃ → P(y₃) = a 第 3 步：把「am」喂回去 a → s₄ → P(y₄) = student student→ s₅ → P(y₅) = <EOS> 第 5 步：生成结束符，停止 一句话： 解码器是一台“把上一个词和源句信息揉在一起、吐出下一个词”的机器，逐词喂回自己 。 东北大学软件学院 · 自然语言处理 14
第 15 页：完整数据流：一张图装下所有零件 环节二 · 知识点讲解 完整数据流 编码器：源句 → 每个位置的隐状态 Je suis étudiant ↓ 查词向量表（embedding）↓ BiLSTM（双向） h₁ h₂ h₃ 每个位置 2h 维（前向 + 后向拼接） ↓ 取两端最后一个状态 c = [ h→₃ ; h←₁ ] 整句压成一个定长向量（本页仍无注意力） 解码器：s₀ = tanh(W·c)，自回归逐词生成 <BOS> → [LSTM] → s₁ → softmax → I I → [LSTM] → s₂ → softmax → am am → [LSTM] → s₃ → softmax → a a → [LSTM] → s₄ → softmax → student student → [LSTM] → s₅ → softmax → <EOS> 输出词由采样 / 取最大得到，再喂回下一步；遇到 ⟨EOS⟩ 停止 训练与推理的不对称 训练 ：目标句的真实前缀全部已知，可以把它整句一次喂进解码器—— 1 次前向算完 m 个位置 ，损失一次算齐、梯度一次回传。 推理 ：只能生成一个词、把它喂回去、再生成下一个—— m 次串行前向 。 教学举例：目标句 20 词，训练 1 次前向，推理 20 次。 “训练快、推理慢”是 Seq2Seq 的固有不对称 （第 14 讲 KV Cache 要治的就是它）。 实现时的三个关键点 训练时用 shifted right ：解码器输入是 [BOS, y₁, …, y_{m−1}]，目标是 [y₁, …, y_m, EOS] 用 mask 屏蔽 PAD 位置，损失只算有效 token 把 c 作为解码器的初始状态（或作为每步的额外输入）——两种实现都可，需在报告中写明 东北大学软件学院 · 自然语言处理 15
第 16 页：架构易错点：五个高频误解 环节二 · 知识点讲解 误解 正确说法 为什么会错 “c 是最后一个词的含义” c 是 整句的定长压缩表示 符号 c 取自最后一步（c = hₙ），看起来像局部量 “解码器每步输入源句的词” 输入 目标端上一步的词 的嵌入；源句只经 c 进入 与第 9 讲序列标注的“逐位置输入源词”混淆 “c 在每个解码步都会更新” 无注意力版本中 c 是 常数 ，所有步共用 把有注意力的 cₜ 与无注意力的 c 混为一谈 “编码器和解码器共享参数” 两套 独立参数 ，各自训练 受“参数共享”的 RNN 印象影响（共享发生在时间维，不是编码/解码之间） “训练时用模型自己的预测” 训练用 真实前缀 （教师强制）；用自预测会难以收敛 没区分训练与推理两个阶段 一个自检方法 把符号写在纸上，逐个标注： 这个量的形状是什么？它在哪一步被计算？它下一步喂给谁？ 三个问题答清楚，上面五条误解都不会犯。 东北大学软件学院 · 自然语言处理 16
第 17 页：信息瓶颈：一个固定向量装不下一个长句 环节二 · 知识点讲解 · 考点 1 容量视角 需求侧 ：源句信息量上界约 n · log₂V 比特，随手长 线性增长 。 供给侧 ：c 的容量由维度 d 决定（如 512 或 1000）， 与 n 无关 。 需求线性增长、供给恒定 → 必然有损压缩 。5 个词的句子够用，50 个词就不够了。 2 优化视角 c 由编码器在读完源句时 一次性确定 ，却要同时对 所有 解码步负责。 因此它只能是所有位置的 折中 ：偏向任何一处，都会牺牲其他处。 而这个折中发生在 看到目标句之前 ——它无法知道后面会需要哪部分信息。 3 近因效应 RNN 的隐状态天然偏向 最近看到的词 （第 8 讲的梯度衰减在起作用）。 结果是：句尾信息保留较好， 句首信息衰减最快 ——而句首往往是主语，承载关键信息。 必须说清的一句判断 这个瓶颈是 结构性的，不是训练不够 ：堆更多数据、换更大模型都不会让它消失，因为『容量常数 vs 需求线性』的矛盾写在架构里。唯一的出路是 不要压成一个向量 ——保留全部隐状态，让解码器每步自己去取。 东北大学软件学院 · 自然语言处理 17
第 18 页：实验证据：BLEU 随句长的两条曲线 环节二 · 知识点讲解 论文原图：BLEU 随句长变化 原图：Bahdanau, Cho & Bengio (2015), Figure 2 RNNencdec-50（无注意力） ：20 词后断崖式下跌，长句 BLEU 掉到 20 以下 RNNsearch-50（有注意力） ：几乎不随句长衰减，50 词以上仍保持稳定 读这条曲线的三件事 两条曲线在 短句上差距不大 ——瓶颈只在长句暴露 无注意力版本在 20 词后断崖 ，正是容量矛盾的体现 有注意力版本 几乎水平 ，甚至在自己训练时见过的最大长度之外仍表现稳定 为什么会泛化到更长句 注意力学到的是一种 对齐关系 （“生成这个词时该看哪几个源位置”），而不是把整句死记硬背进一个向量。 对齐关系是 局部、可复用的 ——句子再长，同一个词对齐同一个源词的规律不变。 这条曲线的历史地位 它成了后来所有长序列工作的 参照实验 ：任何声称“能处理长文本”的方法，都要回答同一个问题—— 性能随长度怎么变？ 左图即论文原图（ Bahdanau, Cho & Bengio 2015, Figure 2 ）；考试只要求 说出趋势与原因 ：无注意力长句崩、有注意力平稳、原因是动态取值代替固定压缩。 东北大学软件学院 · 自然语言处理 18
第 19 页：三种缓解方案：为什么只有注意力够 环节二 · 知识点讲解 方案 做法 效果与代价 为什么治不了本 ① 加深加宽 堆多层 LSTM、增大隐层维度（Sutskever 用 4 层） 短句明显提升，深层确实优于浅层；但成本剧增、边际递减 容量仍然是 常数 ，长句曲线依旧下行 ② 双向编码器 每个位置拼接前向与后向隐状态 每个位置都能看到全句，缓解近因效应，实用且几乎无代价 最终仍要压成一个 c ，瓶颈原封不动 ③ 倒序输入源句 把源句反转后再送进编码器（Sutskever 2014 的技巧） 让句首词离 c 更近，BLEU 有可观提升，实现零成本 只是把瓶颈 往后推 一点，本质不变 ④ 注意力 保留全部 h₁…hₙ，解码每步动态加权取用 长句不再衰减；额外代价只是每步 O(n) 的加权计算 不压缩 ：从根上取消了“固定容量”这个前提 一句话对比 前三条路都在 “怎么压得更好” 上做文章；注意力换了个问题： “为什么一定要压？” ——把 n 个隐状态全部留着，解码时按需取用。信息通路从『递归传递』变成『直接查表』。 这也是本讲最值得带走的方法论： 当优化做到极限仍不奏效时，回头质疑前提本身 。 东北大学软件学院 · 自然语言处理 19
第 20 页：注意力机制：每步解码都“回头看” 环节二 · 知识点讲解 · 考点 人的翻译过程 译出“student”时，你会盯着源句里的“étudiant”；译出“I”时，你盯着“je”。 注意力不是均匀回忆整句，而是有的放矢地看相关位置。 Bahdanau 等 2014（ICLR 2015）的论文标题就是全部思想： Jointly Learning to Align and Translate —— 对齐与翻译一起学 。 无注意力：c 固定，对所有 t 相同 P( yₜ | y<ₜ , c ) ← 一个 c 管到底 有注意力：c_t 每步重算 cₜ = Σ j=1..n α tj · h j α tj = softmax j ( e tj ) e tj = a( s t−1 , h j ) ← 相关性打分 P( yₜ | y<ₜ , cₜ ) ← 每步换一个上下文 查询来自解码器 s t−1 是“我现在想生成什么”的状态——相当于检索时的 查询 。 被查的是编码器输出 h j 是每个源位置的表示——相当于检索时的 索引项 。 结果是一个加权平均 c_t 不是某一个 h_j，而是 按相关性混合出的新向量 ——因此可以表达一对多、多对一关系。 一句话： 把“一次压缩、全程共用”换成“全部保留、按需加权读取” ——这就是注意力的全部内容。 东北大学软件学院 · 自然语言处理 20
第 21 页：注意力三步：打分 → 归一化 → 加权求和 环节二 · 知识点讲解 · 考点 注意力计算：三步 ① 打分 score e tj = a( s t−1 , h j ) j = 1 … n 衡量当前解码状态与第 j 个源位置的相关性；原始分数可正可负、量纲任意、未归一化 ② 归一化 softmax，对 j 做 α tj = exp(e tj ) / Σ k exp(e tk ) 非负 + 整行加起来 = 1 → 可解释为“注意力分配比例” ③ 加权求和 生成动态上下文 cₜ = Σ j α tj · h j ∈ R 2h 不是取某一个 h_j，而是按权重混合出新的向量；维度与 h_j 相同（2h） 四个关键细节 三步顺序 不能换 ：先打分才能归一化，归一化后才能加权 softmax 是 对源位置 j 做的（每个解码步做一次），不是对解码步做 c_t 的维度与 h_j 相同（2h）——但它是按需生成的，不再是被迫压缩 α 是 权重比例 ，不是“选中某个词的概率”，全部位置都被加权混合 两个必背公式 α tj = softmax j ( a( s t−1 , h j ) ) cₜ = Σ j α tj h j 考试常考：写出这两式 + 说明每步在做什么 + 手算一个小例子。 东北大学软件学院 · 自然语言处理 21
第 22 页：打分函数：dot / general / additive / 缩放点积 环节二 · 知识点讲解 · 考点 名称与出处 公式 参数量 特点与适用 dot （Luong 2015） e = s T h 0 最快，可用矩阵乘一次算完；要求 s 与 h 同维 ；现代实现主流 general （Luong 2015） e = s T W h d×d 允许 s 与 h 维度不同；表达力更强，Luong 推荐之一 concat / additive （Bahdanau 2015） e = v T tanh( W [ s ; h ] ) 较大 拼起来过一层再打分，表达力最强、参数最多；维度可不同 缩放点积 （Vaswani 2017） e = s T h / √d 0 点积的改良：维度大时点积数值很大、softmax 会饱和，除以 √d 稳住梯度。 第 11 讲的主角 Bahdanau 与 Luong 的四个差别 维度 Bahdanau 2015 Luong 2015 查询用什么 s t−1 （上一步状态，未含本步输入） s_t （本步状态） 编码器用哪层 双向拼接（底层，词级信息多） 顶层（抽象程度高） 打分函数 只有 additive dot / general / concat 三种 额外技巧 — local attention （限制窗口） 工程上怎么选 默认用 dot 或缩放点积 ：无参数、可用矩阵乘法批量算、实现简单、速度最快。 只有在“查询与被查向量维度必须不同”或“需要更强表达力”时才用 general / additive。 实践数据 ：在多数翻译任务上，四种打分函数最终 BLEU 差别不大，但 速度差别明显 ——工程上优先选快的。 东北大学软件学院 · 自然语言处理 22
第 23 页：Luong 局部注意力：全局 vs 局部 环节二 · 知识点讲解 Global 全局注意力 cₜ = Σ j=1..n α tj h j ← 全部 n 个位置 每步代价 O(n) ，整句 O(m·n) 无对齐先验假设， 语序重排自由 （适合翻译） n 很大时（文档级、长音频）开销明显 今天绝大多数实现的默认选择 Local 局部注意力 ① 先预测对齐中心 pₜ 单调变体： pₜ = t （假设语序一致） 预测变体： pₜ = n·σ( v T tanh( W sₜ ) ) ② 只在窗口 [ pₜ − D , pₜ + D ] 内算注意力 cₜ = Σ j ∈ 窗口 α tj h j 代价降到 O(m·D) ，D 通常取 5–10 “先粗定位、再细对齐”——符合人做长文档翻译的直觉 代价：需要额外学习对齐中心；假设对齐近似单调 为什么今天仍然用全局注意力 因为在 GPU 上， 全局注意力的矩阵乘法可以被高度并行、批量算完 ，而局部注意力引入的窗口选择会带来不规则的计算模式，实际速度未必更快。工程上『理论复杂度』与『实际吞吐』经常不是一回事——这是本讲要培养的另一种判断力。 考点： 能说出全局与局部的代价差（O(m·n) vs O(m·D)）与各自适用场景 即可，不要求推导 p_t。 东北大学软件学院 · 自然语言处理 23
第 24 页：手算一步注意力 ①：打分与 softmax 环节二 · 知识点讲解 · 手算考点 题设：源句 3 个词，编码器隐状态 h₁ = [1, 0] 、 h₂ = [0, 1] 、 h₃ = [1, 1] ；当前解码状态 s = [1.0, 0.5] ；打分函数取 dot 。求注意力权重 α 与动态上下文 c。 1 逐位置打分 e_j = s · h_j e₁ = [1.0, 0.5] · [1, 0] = 1.0×1 + 0.5×0 = 1.0 e₂ = [1.0, 0.5] · [0, 1] = 1.0×0 + 0.5×1 = 0.5 e₃ = [1.0, 0.5] · [1, 1] = 1.0×1 + 0.5×1 = 1.5 第 3 个源位置得分最高（1.5）——说明 当前解码状态最需要第 3 个位置的信息 。 2 softmax 归一化 exp(e₁) = exp(1.0) = 2.718 exp(e₂) = exp(0.5) = 1.649 exp(e₃) = exp(1.5) = 4.482 ──────────────────────────── 和 = 8.849 α₁ = 2.718 / 8.849 = 0.3072 α₂ = 1.649 / 8.849 = 0.1863 α₃ = 4.482 / 8.849 = 0.5065 和 = 1.0000 ✓ 读这三组数的含义 α₃ ≈ 0.51 最大：模型把一半注意力放在第 3 个源词上；α₁ ≈ 0.31 次之；α₂ ≈ 0.19 最小。 但三个位置都拿到了非零权重 ——这是软对齐（soft alignment）的特征，与“硬选一个词”有本质区别。 三个易错点 忘记 softmax 是 对 j（源位置） 做的，而不是对不同的解码步 用 e 直接当权重（未归一化），导致 c 的量纲失控 精度不够：手算时至少保留 4 位小数，否则最后 α 之和不为 1 东北大学软件学院 · 自然语言处理 24

第 28 页：意义 ②③：软检索与免费的对齐 环节二 · 知识点讲解 意义②：注意力 = 一次“软检索”（Q/K/V 隐喻） 检索概念 注意力里的对应物 Query 查询 q = s t ——“我现在需要什么信息” Key 键 K = [h₁ … h n ]——每个源位置的“匹配面” Value 值 V = [h₁ … h n ]——每个源位置的“内容面” 相似度计算 ① e j = score( q , K j ) 归一化成权重 ② α j = softmax( e j ) 加权返回结果 ③ c = Σ α j V j 这套 Q/K/V 语言就是第 11 讲自注意力的全部术语来源。 今天把这三步弄懂，第 11 讲就不会觉得是新东西。 意义③：对齐成了免费的副产品 统计翻译时代 ：需要独立训练对齐模型（IBM Model / GIZA++），先算出词级对齐，再抽短语表——流程庞大且昂贵。 神经注意力 ：把对齐变成训练过程中的 涌现结果 ，不需要任何对齐标注。论文标题 jointly learning to align 说的正是这件事。 工程价值 ：热图直接给出“哪个目标词看了哪些源词”，可用于漏译排查与术语一致性检查。 但要打折扣 ：α 是加权比例，不是选词概率；后续层还有非线性变换。热图是 诊断线索 ，不是因果解释。 这三条意义合起来就是： 动态取值（解决瓶颈）+ 软检索（提供机制）+ 免费对齐（带来可解释性） 。 东北大学软件学院 · 自然语言处理 28
第 29 页：注意力易错点：六个高频误区 环节二 · 知识点讲解 误区 纠正 一句话记忆 “注意力让模型看到新信息” 用的还是那批 h_j，只是改变了 读取方式 不增加信息，只重新分配 α “α 可以当翻译词典” 无监督涌现的副产品，可一对多、多对一 可视化 ≠ 词典 “热图就是模型的解释” α 是加权比例，后续还有非线性变换 诊断线索 ≠ 因果证据 “α 是选中某个词的概率” 全部位置 都被加权混合，只是比例不同 是“混合比例”，不是“选择概率” “注意力一定提升所有任务” 短句或对齐简单的任务上增益有限，还要付出 O(m·n) 代价 收益与句长、对齐难度正相关 “注意力解决了串行问题” 编码器与解码器 仍是串行 RNN ，一个时间步一次计算 这正是第 11 讲 Transformer 的动机 最后一条要特别强调 注意力解决了『解码器读源句』的瓶颈，但 没有解决『RNN 必须一步一步算』的瓶颈 。训练时序列长度为 n 就要 n 次串行计算，GPU 的并行能力大量闲置。这个大问题，要等到第 11 讲把循环整体换掉才能解决。 东北大学软件学院 · 自然语言处理 29
第 30 页：训练：教师强制（Teacher Forcing） 环节二 · 知识点讲解 · 考点 两种模式对照 阶段 第 t 步的输入 后果 训练 teacher forcing 真实的上一个目标词 y t−1 稳定、好收敛； 可并行 （前缀已知，一次前向算完） 推理 free running 模型自己刚生成的词 ŷ t−1 一步错 → 步步错，误差滚雪球 名字由来： 老师把标准答案一个字一个字喂给学生 ，学生永远在“正确的上文”上练习下一步。 为什么训练必须用教师强制 早期模型输出全是错的，用自预测会让输入分布迅速跑偏， 极难收敛 真实前缀已知 → 解码器可在 一次前向 里并行计算 m 个位置（加三角 mask 防止看到未来） 梯度信号干净：每个位置的损失对应一个明确的目标词 代价：模型 从未在训练中见过自己的错误 ——这直接导致下一页的暴露偏差。 训练（输入 = 真实前缀，一次前向并行算完 m 个位置） 解码器输入：<BOS> I am a student 目标（标签）： I am a student <EOS> 推理（输入 = 自生成前缀，m 次串行前向） <BOS> → 生成 I → 把 I 喂回 → 生成 am → 把 am 喂回 → … → <EOS> 记忆锚点： 训练时输入是“标准答案的前缀”，推理时输入是“自己的答案的前缀” ——两者分布不同，这是暴露偏差的根源。 东北大学软件学院 · 自然语言处理 30
第 31 页：暴露偏差：训练与推理的输入错位 环节二 · 知识点讲解 · 考点 定义与后果 训练: 输入 = 真实前缀 y<t （永远正确） 推理: 输入 = 自生成前缀 ŷ<t （可能出错） 模型从未在训练中见过自己的错误 → 一步小错让后续状态偏离训练分布 → 误差累积（滚雪球） 典型症状 ：重复生成同一个词或短语（卡住）；话题漂移；句子越长、后半段质量越差；有时陷入“复读机”模式。 这个现象最早由 Bengio 等 2015 系统讨论并命名。 三种缓解手段（都是缓解，不是根治） 计划采样（scheduled sampling） ：训练时以概率 ε 混入模型自己的预测，ε 随训练从 0 逐渐增大——让模型逐步适应“自己的错误”。代价：训练更慢、不稳定，实践收益有限 Beam search ：推理时保留多个候选，降低单步错误造成的伤害 数据与目标改造 ：加入噪声、用强化学习直接优化序列级指标（BLEU） 一个重要的历史判断 暴露偏差是 所有自回归生成模型的共同问题 ，不只是 seq2seq 的。今天你看到大模型有时“越说越偏”“陷入重复”，背后依然是同一个结构性问题： 训练时看真实文本，推理时看自己生成的内容 。区别只在于规模与缓解手段的丰富程度。 考点提示： 能说出定义、症状与至少两种缓解方案 即可，不要求推导计划采样的概率公式。 东北大学软件学院 · 自然语言处理 31
第 32 页：解码：搜索空间有多大 环节二 · 知识点讲解 目标：ŷ = argmax y P( y | x ) = argmax y ∏ t P( yₜ | y₁…yₜ₋₁ , x ) 搜索空间：|V| m 个候选序列 教学举例：|V| = 30,000，m = 20 → 候选数 ≈ (3×10⁴)²⁰ = 3²⁰ × 10⁸⁰ ≈ 10⁹⁰ → 比可观测宇宙的原子数（约 10⁸⁰）还多 策略 做法 复杂度 特点与适用 穷举 枚举全部候选序列 |V| m 理论最优， 完全不可行 贪婪 Greedy 每步取概率最大的词 O(m · V) 最快、确定、可复现；但不看未来、易错过更优解 束搜索 Beam 每步保留 k 条最优前缀 O(m · k · V) 质量最好、工业标配；k 越大越慢，质量并非单调提升 采样 Sampling 按分布抽样，可加温度 / top-k / top-p O(m · V) 多样、适合对话与创意写作； 不可复现 （除非固定种子） 一个常被忽略的问题 训练目标是逐词交叉熵，评测却是整句 BLEU ——两者口径不一致。降低交叉熵不一定提升 BLEU，这就是后来“序列级训练 / 强化学习”的动机。 工程规范提醒 提交作业或论文时 必须写明解码参数 ：greedy 还是 beam？k 是多少？有没有长度惩罚？温度多少？ 不写解码参数 = 结果不可复现，这是工程规范问题。 东北大学软件学院 · 自然语言处理 32
第 33 页：贪婪解码：每步只取最大 环节二 · 知识点讲解 定义与复杂度 ŷₜ = argmax w P( w | y₁ … yₜ₋₁ , x ) 每步：1 次 softmax + 1 次 argmax 总代价： O( m · V ) beam search 在 k = 1 时的特例 完全 确定、可复现 （同样的输入必得同样的输出） 实现最简单、 延迟最低 ——实时翻译、流式场景的首选 不回头、不考虑未来的分支 短视的代价：一个两分支小例子 第 1 步： P(A) = 0.50 P(B) = 0.30 → 贪婪选 A（局部最大） 第 2 步： 若走 A：最优后继 P(x|A) = 0.10 若走 B：最优后继 P(p|B) = 0.90 联合概率： A x = 0.50 × 0.10 = 0.050 B p = 0.30 × 0.90 = 0.270 ← 全局更优 贪婪输出「A x」，而真正的最优是「B p」 这与第 9 讲『贪心标注 vs Viterbi』是同一个道理： 局部最优 ≠ 全局最优 。 什么时候贪婪够用 当模型非常自信（每步分布都很尖）时，贪婪与 beam search 的输出差别很小； 延迟敏感 + 模型训练充分 的场景，贪婪往往是性价比最高的选择。这也是很多线上系统的实际做法。 东北大学软件学院 · 自然语言处理 33
第 34 页：Beam Search：保留 k 条最优前缀 环节二 · 知识点讲解 · 考点 算法（束宽 k = 2 的例子） ① 初始化：束 = { <BOS> : 1.0 } 空前缀，分数 1.0（log 空间为 0） ② 扩展：对束中每条前缀，计算「父分数 × P(w | 前缀)」 → 得到 k × V 个候选 ③ 剪枝：全局排序，只保留 top-k 条 ④ 终止：出现 <EOS> 的前缀移入「完成池」，不再扩展但保留比较 ⑤ 输出：在完成池 + 未完成前缀中选最终最优（ 需长度归一化 ） 三个实现要点 累加 对数概率 而不是概率连乘——连乘会下溢变成 0 已完成的前缀 不再扩展 ，否则浪费束宽 最后 必须做长度归一化 ，否则系统性偏好短句（下一页详讲） 复杂度与参数选择 每步 O(k · V) 次打分（实际用矩阵运算批量做），总 O(m · k · V) ——比 greedy 慢 k 倍，但远小于穷举 |V| m 。 经验取值 ：机器翻译 k 常取 4–12 ；对话与摘要常用 3–5；实时场景可用 1–3。 一个反直觉的结论 k 越大不等于质量越高。 Murray & Chiang 2018 的实证研究显示，BLEU 随 k 增大先升后降：束太宽会让模型倾向于“高概率但平庸”的句子，反而偏离人类偏好。 而且模型概率与人类质量评价 并不完全一致 ，搜索得越彻底，有时越明显暴露这个偏差。 记忆锚点： beam search = 每一步都“保留几个最像样的草稿”，最后挑一份交卷 。 东北大学软件学院 · 自然语言处理 34
第 35 页：Beam Search 逐步演算（k = 2） 环节二 · 知识点讲解 · 手算考点 步骤 候选计算（父分数 × 条件概率） 保留 top-2 被剪掉的 第 1 步 P(A) = 0.50 P(B) = 0.30 P(C) = 0.20 A : 0.50 B : 0.30 C : 0.20 永久出局 第 2 步 从 A：Ax = 0.50×0.40 = 0.200 Ap = 0.050 A<EOS> = 0.250 从 B：Bx = 0.30×0.60 = 0.180 Bp = 0.030 B<EOS> = 0.090 A<EOS> : 0.250 （完成） A x : 0.200 Bx 0.180、B<EOS> 0.090、Ap、Bp 第 3 步 只有 Ax 可继续： Axy = 0.200×0.90 = 0.180 Ax<EOS> = 0.200×0.10 = 0.020 A x y : 0.180 Ax<EOS> : 0.020 —（束未满，全部保留） 最终比较：长度归一化改写了答案 候选 长度 L 概率 P log P 未归一化排序 A<EOS> 1 0.250 −1.386 ← 原始 logP 最优 A x y 3 0.180 −1.715 Ax<EOS> 2 0.020 −3.912 长度归一化（α = 0.7）： score = logP / L^0.7 A<EOS> : −1.386 / 1^0.7 = −1.386 A x y : −1.715 / 3^0.7 = −0.795 ← 归一化后最优 Ax<EOS> : −3.912 / 2^0.7 = −2.393 这个演算教会我们三件事 剪枝是不可逆的 ：第 1 步被剪掉的 C，后面再高的概率也回不来 完成的假设要留着 ：A<EOS> 在第 2 步就完成了，但它仍是最终候选之一 必须做长度归一化 ：否则短句占尽便宜，模型会学会“早出 EOS 拿高分” 所以工业系统的 beam search 一定带 长度惩罚 α （常取 0.6–0.7）。 东北大学软件学院 · 自然语言处理 35
第 36 页：长度归一化与覆盖惩罚 环节二 · 知识点讲解 · 考点 隐蔽 bug：长度偏置 累计 logP 是一串 负数相加 ，句子越长总分越低（越负）。 后果：beam 系统性 偏好短句 ；极端情况下模型学会“ 早出 <EOS> 拿高分 ”——只生成一两个词就结束。 这是解码期的问题， 不改模型参数、只改打分方式 就能解决。 解法：长度归一化 score( y ) = ( Σ t log P( yₜ | y<ₜ , x ) ) / L α α = 0 → 原始 logP（ 偏好短句 ） α = 1 → 完全除以长度（可能偏好长句） α = 0.6–0.7 → 工业常用 （GNMT 用 0.6） 覆盖惩罚（coverage penalty） cp( y , x ) = β · Σ j=1..n log( min( Σ t α tj , 1.0 ) ) score = logP / L α + cp( y , x ) β 常取 0.2–0.4 直觉 ：把每个源位置在整个解码过程中累计收到的注意力加起来。如果一个位置被反复过度关注（Σα 远大于 1），说明模型在“重复翻译同一处”；如果某个位置的累计注意力接近 0，说明“漏了”。 这个惩罚项会同时 抑制重复 与 缓解漏译 ——GNMT 报告它带来明显提升。 一个重要的方法论 长度归一化与覆盖惩罚都属于 解码期的后处理 ：模型没变、参数没变，只是改了一句排序规则，效果就有可观改善。 “训练—解码—评估”三处都可以做优化，不要只盯着模型结构。 东北大学软件学院 · 自然语言处理 36
第 37 页：反例：Beam Search 也会错过全局最优 环节二 · 知识点讲解 沿用 k = 2 的算例，只改后续概率 真正的“最优句”必须以 C 开头： 第 1 步 P(C) = 0.20 ← 排名第 3， 被剪掉 第 2 步 P( x | C ) = 0.99 第 3 步 P( y | C x ) = 0.99 → 联合概率 = 0.20 × 0.99 × 0.99 ≈ 0.196 beam 实际输出 A<EOS> = 0.250，看似更高； 但若把 C 分支后续换成 0.999： Cxy ≈ 0.1997 仍被排在 A<EOS> 之后 —— 关键问题是：C 分支在第 1 步就永久出局， 后面无论多好都没有机会参与比较。 为什么会这样 beam search 在 每一步 都做局部剪枝——它只是比 greedy 保留更多候选，本质上仍是贪心。 一个开头概率不高、但后续极好的序列，可能在第一步就被淘汰。 结论：beam search 是近似搜索，不保证全局最优。 与第 9 讲 Viterbi 的关键区别 Viterbi（第 9 讲） Beam Search 是否精确最优 在 HMM/CRF 假设下精确 只是近似 为什么 最优子结构成立，剪掉的路径不可能更优 语言模型的条件依赖没有严格马尔可夫性，剪枝无保证 保留几条 每格只留 1 条（最优） 每步留 k 条 实践建议 k 增大到一定程度后收益递减，而延迟线性增长 想要更接近最优，可以结合 采样 + 重排 （生成多个候选再用另一个模型打分） 在延迟敏感场景，greedy 往往是最优性价比选择 东北大学软件学院 · 自然语言处理 37
第 38 页：采样策略：temperature · top-k · top-p 环节二 · 知识点讲解 · 考点 策略 做法 特点 适用与坑 Temperature P′ᵢ ∝ exp( zᵢ / T )，再 softmax T→0 逼近 greedy；T=1 原始；T>1 更平更随机。连续可调 “稳定 ↔ 多样”的连续旋钮；T 过大产生胡言乱语 Top-k 只保留概率最高的 k 个词，重新归一化后抽样 候选数量 固定 ，过滤长尾噪声 k 太小文本呆板重复；k 太大噪声回归 Top-p （核采样） 取累计概率刚超过 p 的 最小集合 ，再抽样 候选集合 随分布自适应 ：模型越确定，候选越少 比 top-k 更稳健；p 常取 0.9–0.95 组合使用 温度 + top-p 是最常见的生产配置 先调分布形状，再截断长尾 参数必须记录，否则结果不可复现 用一个分布直观对比（P = [好 .50, 吃 .30, 睡 .15, 打 .05]） T = 0.5 → 分布变尖，几乎总是选“好” T = 1.0 → 按原始比例抽 T = 1.5 → 分布变平，“打”(0.05) 也被抽到 top-k, k = 2 → 只在 {好, 吃} 里按 0.625 / 0.375 抽 top-p, p = 0.8 → 候选集 = {好, 吃, 睡}（累计 0.95 超过 0.8 的最小集合） 怎么选 机器翻译 ：beam search（要确定性、要质量）。 对话与创意写作 ：采样 + 温度（要多样性）。 代码生成 ：低温 + top-p（要准确、要可编译）。 需要复现的评测 ：greedy 或 beam + 固定随机种子。 伏笔： 第 14 讲会用真实 LLM 系统测试这些参数对幻觉、重复与质量的影响 。今天先建立“选词方式是可调旋钮”的概念。 东北大学软件学院 · 自然语言处理 38
第 39 页：BLEU：机器翻译怎么自动打分 环节二 · 知识点讲解 · 考点 总公式（Papineni 等，2002） BLEU = BP × exp( Σ n=1..N w n · log p n ) N = 4（常用），w n = 1/N = 1/4 p n = 修正后的 n-gram 精确率 BP = 简短惩罚 Brevity Penalty 三个组件各管什么 p₁（unigram） ：用词是否准确——词汇选对了没有 p₂–p₄ ：语序与搭配是否通顺——词组用得对不对 BP ：防止“越短越占便宜”——短句要受罚 几何平均把四个层次的信息合成一个数，取值 0–1（常乘 100 写成百分数）。 最著名的脆弱点 因为用的是 几何平均 （对数后求平均再取指数），只要 任何一个 p_n = 0 ，log 0 = −∞， 整个 BLEU 就是 0 。 所以一个译文即便 1–3 gram 全对、只有 4-gram 没匹配上，BLEU 也会是 0——这个性质在实际使用中非常容易造成误判。 为什么要 4 个 n-gram 只用 unigram 精确率，模型会倾向输出高频词堆砌（“the the the”）；只用高阶 n-gram 则过于苛刻、样本稀疏。 1–4 gram 的几何平均是一个 折中：既看用词，也看短语与语序 。 BLEU 的设计哲学： “机器译文里的 n-gram 有多少出现在参考译文里” ——它是一个精确率导向的指标，天生不擅长衡量召回与语义。 东北大学软件学院 · 自然语言处理 39
第 40 页：修正 n-gram 精确率与截断计数 环节二 · 知识点讲解 · 考点 论文经典反例：重复就能拿满分 候选: the the the the the the the (7 个词) 参考: the cat is on the mat (含 2 个 the) 未修正的 unigram 精确率 = 7 / 7 = 1.00 ← 垃圾句满分！ 修正规则（截断计数） 对于每个 n-gram w： Count clip (w) = min ( 候选中的计数 , 参考中的最大计数 ) 本题： Count clip (“the”) = min( 7 , 2 ) = 2 修正后 p₁ = 2 / 7 ≈ 0.286 多参考时的处理 ：参考译文往往有多个（如 4 个）。此时『参考中的最大计数』取多个参考里该 n-gram 出现的 最大值 。 这个机制为什么重要 它让 BLEU 不会因重复输出而虚高 ——朴素精确率做不到这一点 它隐含了“参考译文里有的才算对”的 保守立场 ，这也是 BLEU 偏向精确率的根源 工程实现需注意效率：把候选的 n-gram 逐个与所有参考的计数比对，常用 Counter 提前汇总 把这一页与下一页连起来看： 截断计数治的是“重复刷分”，BP 治的是“越短越占便宜” ——一个指标的每一个设计，往往都对应一个曾经被钻过的漏洞。 东北大学软件学院 · 自然语言处理 40
第 41 页：简短惩罚 BP：治“越短越占便宜” 环节二 · 知识点讲解 · 考点 漏洞与公式 漏洞 ：精确率导向 → 候选越短越容易“词词都在参考里”。只输出 the 一个词时 p₁ = 1，而高阶 n-gram 无定义，BLEU 虚高。 BP = 1 若 c > r BP = exp( 1 − r / c ) 若 c ≤ r c = 候选译文长度（词数） r = 有效参考长度 = 与 c 最接近 的那个参考的长度 算几个数直观感受 c = 12, r = 12 → BP = 1 不惩罚 c = 10, r = 12 → exp(1 − 1.2) = 0.819 c = 6, r = 12 → exp(1 − 2.0) = 0.368 c = 3, r = 12 → exp(1 − 4.0) = 0.050 几乎归零 BP 只惩罚 过短 ，不奖励过长——啰嗦的译文要靠精确率本身去扣分。 为什么用『最接近的参考长度』 同一句源文可以有不同长度的合法译文（例如中文“天亮了”可译为 “It's dawn.” 或 “The day has broken.”）。 如果固定用最短参考，会不公平地惩罚较长的正确译文；取 最接近候选长度 的那个参考，能更公平地判断“是否过短”。 一句话总结 BLEU 的两道补丁 截断计数 防“重复刷分”； BP 防“越短越占便宜”。两者都是被实际漏洞逼出来的工程补丁——这也是所有自动评测指标的共同演化方式。 东北大学软件学院 · 自然语言处理 41
第 42 页：例题：把一个句子的 BLEU 算到底 环节二 · 知识点讲解 · 手算考点 题设：候选 C = the cat is on the mat today （c = 7） 参考 R = the cat is on the mat （r = 6） n 候选 n-gram（个数） 匹配（截断后） p n 1 the×2, cat, is, on, mat, today the(2), cat, is, on, mat = 6 （today 不在参考里） 6/7 ≈ 0.857 2 the cat, cat is, is on, on the, the mat, mat today（6） 前 5 个全匹配； mat today 无匹配 5/6 ≈ 0.833 3 the cat is, cat is on, is on the, on the mat, the mat today（5） 前 4 个匹配；the mat today 无匹配 4/5 = 0.800 4 the cat is on, cat is on the, is on the mat, on the mat today（4） 前 3 个匹配；最后一个无匹配 3/4 = 0.750 计算过程 BP：c = 7 > r = 6 → BP = 1 （不惩罚） 几何平均（取自然对数后求平均）： ln(0.857) = −0.1542 ln(0.833) = −0.1823 ln(0.800) = −0.2231 ln(0.750) = −0.2877 ──────────────────── 和 = −0.8473，除以 4 → −0.2118 BLEU = exp( −0.2118 ) ≈ 0.809 ≈ 0.81 （若按百分数报告： 81.0 ） 三个易错点 忘记 截断计数 ：重复的 n-gram 只按参考里的最大计数算 把 BP 用反：只有 c ≤ r 时才惩罚，c > r 时 BP = 1 忘记高阶 n-gram 为 0 会让 整个 BLEU 归零 ——本例 p₄ = 0.75 非零，所以正常 动手练习 ：把候选里的 today 换成 the（长度仍为 7），重新算一遍 p₁——你会看到截断计数的作用。 东北大学软件学院 · 自然语言处理 42
第 43 页：BLEU 的六条局限 环节二 · 知识点讲解 · 考点 局限 具体表现 后果与应对 ① 只看字面 同义改写被误判：参考是 big、候选是 large → 扣分，但译文是对的 无法奖励“换个说法也对”→ 用语义类指标（BERTScore） ② 精确率导向 抓不住 漏译 ；BP 只是粗补偿 摘要任务尤其危险 → 用召回类指标（ROUGE） ③ 参考不足 一句源文可能有几十种合法译法，参考通常只有 1–4 个 “没匹配上”不等于“翻错了”→ 多参考 + 人工抽检 ④ 不管语义与语用 语法正确但意思错的译文可能拿到不低的分数 关键场景必须做人工评估或语义指标 ⑤ 对分词敏感 中文按字切还是按词切，BLEU 数值差别很大 跨系统比较必须 统一分词口径 并写进报告 ⑥ 句子级方差大 单句 BLEU 很不稳定（一句话的 4-gram 匹配太少） 只在 语料级 报告；句子级比较需谨慎 正确的使用态度 BLEU 的价值在于 快速、可复现、可自动化 的相对比较（A 系统比 B 系统好多少），而不在于给出一个绝对的质量结论。 指标是工具，不是判决。 这条判断适用于后面所有大模型评测指标。 东北大学软件学院 · 自然语言处理 43

第 45 页：应用族谱：一个骨架，多种模态 环节二 · 知识点讲解 模态转换 代表工作 注意力在这里对齐什么 文本 → 文本 GNMT（Wu 2016）· Pointer-Generator（See 2017）· 对话生成（Vinyals & Le 2015） 源句词序列 → 目标句词序列（软对齐热图） 语音 → 文本 Listen-Attend-Spell（Chan 2016）· LAS：金字塔 BiLSTM + 注意力 + 字符解码器 汉字/字符 ↔ 声学帧： 完全自动学出对齐 ，不需要人工强制对齐 图像 → 文本 Show, Attend and Tell（Xu 2015）图像描述 生成的每个词 ↔ 图像区域：把 α 画回原图，能看到生成 man 时高亮人物、生成 skateboarding 时高亮滑板 文本 → 语音 Tacotron（Wang 2017） 字符 ↔ 音频帧：字与频谱帧的对齐由注意力自动学出，替代传统拼接式合成 结构 → 文本 代码生成、Text-to-SQL、语义解析 自然语言 ↔ 结构化 token（SQL 关键字、括号等） 为什么这些任务能共用一套骨架 它们的共同结构都是： 一段变长输入 → 一段变长输出，且两者之间存在某种（可能非单调的）对应关系 。 注意力负责发现这个对应关系，编码器-解码器负责生成——与具体模态无关。 三个必须知道的工程细节 语音 ：输入帧数远多于输出字符数（约 10:1），所以常用金字塔式下采样缩短时间轴 图像描述 ：把 CNN 最后的特征图每个位置当一个“源位置”，注意力在区域上做加权 文本摘要 ：纯生成会写错事实与专名，需要 复制机制 （下一页） 一句话： seq2seq + 注意力 = 通用“对齐 + 生成”机器 ——这也是它成为深度学习时代第一个通用 NLP 骨架的原因。 东北大学软件学院 · 自然语言处理 45
第 46 页：复制机制：让模型既能“写”也能“抄” 环节二 · 知识点讲解 纯生成式的两个缺陷 写不对事实与专名 ：训练语料里见过“东北大学”，但生成时可能写出“东方大学”——语义相近但事实错误。 未登录词只能输出 UNK ：源句里的新公司名、新药名、数字、日期，词表里没有就写不出来。 容易重复 ：同一句话反复生成。 这些问题在摘要与对话场景尤其致命。 Pointer-Generator 的做法（See 等 2017） ① 生成门（软开关）： p gen = σ( w h ·h* t + w s ·s t + w x ·x t ) ∈ (0,1) ② 混合分布： P( w ) = p gen · P vocab ( w ) ← 从词表“写” + (1 − p gen ) · Σ j : x_j = w α tj ← 从源句“抄” ③ 对未登录专名：把 P vocab (w) 置 0， 强制只能通过复制路径输出，避免 <UNK> 工程价值与代价 价值 ：专名、数字、日期不写错；同时仍能生成源句里没有的概括性表达（例如“该公司宣布……”）。 代价 ：需要复用注意力权重 α，实现比标准 seq2seq 稍复杂；p_gen 的可解释性有限。 这个思想的现代回声 今天所有 RAG 系统都面临同一个问题： 答案里的专名与数字必须来自检索到的原文，不能由模型“编” 。复制机制（检索结果 → 输出）的思路正是这类需求的源头，第 15 讲会把它工程化。 东北大学软件学院 · 自然语言处理 46
第 47 页：RNN 仍是瓶颈：通往 Transformer 的路标 环节二 · 知识点讲解 · 考点 1 串行瓶颈没有被解决 注意力只改变了『解码器读源句』的方式； 编码器与解码器本身仍然是 RNN ，必须一个时间步一个时间步算。 训练时序列长度为 n 就要 n 次串行计算 ，GPU 的并行能力大量闲置。 后果：模型 无法通过单纯堆数据、堆算力来扩展 ——这在 2017 年数据爆炸的背景下成了硬伤。 2 长距离依赖仍受限 注意力给了『解码器 → 编码器任意位置』的 O(1) 通路，但 编码器内部 的信息传递仍要穿过多步 RNN。 第 8 讲的梯度衰减仍在起作用：源句内部两个相隔很远的词，它们之间的信息依旧要“接力”传递。 Transformer 的解法（第 11 讲预告） ① 用 自注意力 替换编码器与解码器里的循环 → 序列内任意两个位置 直接相连 ，路径长度 O(1) → 所有位置 可以并行计算 （矩阵乘一次算完整句） ② 用 位置编码 补回语序信息（自注意力本身与顺序无关） ③ 用 多头注意力 同时学习多种对齐关系（语法、语义、指代……） ④ 用 残差 + LayerNorm 让深层网络稳定可训练 一句话： 注意力解决了“读哪里”的问题，Transformer 解决了“怎么并行地读”的问题 ——而它用的仍然是今天学的打分→归一化→加权求和。 东北大学软件学院 · 自然语言处理 47
第 48 页：收口对比：无注意力 vs 有注意力 环节二 · 知识点讲解 · 复习索引 维度 无注意力（Cho 2014 / Sutskever 2014） 有注意力（Bahdanau 2014 / Luong 2015） 结论 上下文来源 一个 静态 c ，所有解码步共用 每步重算 c_t ，随生成需求变化 后者 信息路径长度 源词 → 目标词要穿过 n 步 RNN O(1) ，打分 + 加权一步直达 后者 信息容量 受 c 维度限制（常数） 全部 h_j 保留、按需取用 后者 长句表现 20 词后 BLEU 断崖下滑 基本平稳，可外推到更长句 后者 计算代价 每步 O(1) 每步 O(n)，整句 O(m·n) 前者（但可并行） 可解释性 无 α 矩阵可可视化，能查漏译 后者 典型系统 RNNencdec RNNsearch · GNMT — 演进线与本讲的位置 RNN Encoder–Decoder（2014.06）→ Seq2Seq（2014.09）→ 注意力（2015）→ GNMT（2016）→ Transformer（2017） 。本讲学到的『打分 → 归一化 → 加权求和』三步，是后续所有大模型的核心运算——第 11 讲只是把它从『解码器查编码器』扩展成『每个位置查所有位置』。 东北大学软件学院 · 自然语言处理 48

第 55 页：本讲小结 环节四 · 小结 1 架构与训练 编码器把源句压成 c ；解码器以 c 为条件 自回归 逐词生成。 训练用 教师强制 （真实前缀，一次前向并行算完）；推理 自由运行 （自生成前缀，m 次串行）→ 由此产生 暴露偏差 。 2 瓶颈与突破 固定 c 的 容量与句长无关 （结构性有损）→ BLEU 随句长断崖下跌。 注意力 保留全部 h_j，用“打分 → 归一化 → 加权求和”每步重算 c_t：路径 O(1) 、上下文动态、对齐成为副产品。 3 解码与评估 greedy（快、可复现）／beam（质量好，需 长度归一化 ）／采样（多样，配温度与 top-p）。 BLEU = BP × 几何平均 n-gram 精确率 （含截断计数）；偏字面、抓不住漏译与同义改写，需配语义/召回类指标与人工评估。 一句话带走 注意力 不增加信息 ，只改变读取方式——从“一次压缩、全程共用”变成“全部保留、按需加权读取”。同样的信息，换一种取用方式，效果就完全不同。这句话贯穿第 11 讲的 Transformer 与第 15 讲的 RAG。 复习索引： 编码器-解码器与 c · 信息瓶颈 · 注意力三步手算 · 打分函数 · teacher forcing 与暴露偏差 · beam search（含长度归一化）· BLEU 计算与局限 。 东北大学软件学院 · 自然语言处理 56
